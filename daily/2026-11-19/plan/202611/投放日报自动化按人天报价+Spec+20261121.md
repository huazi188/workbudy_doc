## 二、技术架构设计

### 系统整体架构

```
客户端层
  ├─ Web 仪表板（React/Vue）
  ├─ 邮件推送（HTML 模板）
  └─ IM 推送（Webhook 到钉钉/飞书）

应用层
  ├─ 数据聚合服务（Python/Node.js）
  ├─ 报告生成服务（Jinja2 模板引擎）
  ├─ 推送服务（定时任务 + 触发规则）
  └─ API 网关（速率限制、权限验证）

数据层
  ├─ 时序数据库（InfluxDB/TimescaleDB）
  ├─ 主数据库（PostgreSQL）
  ├─ 缓存层（Redis）
  └─ 对象存储（S3/OSS）
```

### 关键技术选型

| 组件 | 候选方案 | 推荐方案 | 理由 |
|-----|--------|--------|------|
| **数据聚合** | 自研 vs 开源框架 | 自研 Python | 快速MVP，平台接入少 |
| **定时调度** | Cron vs 消息队列 | Celery + Redis | 可靠性高，易于扩展 |
| **报告生成** | 传统模板 vs LLM | 传统模板 | MVP 阶段保持简单 |
| **推送** | Email + Webhook | 两者 | Email 可靠，IM 实时 |
| **存储** | 关系DB vs 时序DB | 混用 | 明细用关系DB，指标用时序DB |

### MVP Go标准（必须全部满足）

- ✅ **功能完整**：15+ 核心功能已上线

- ❌ API 接入失败：平台API无法稳定调用
