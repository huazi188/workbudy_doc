## 第一部分：国内

### 1. 字节 Vigil：在火山引擎值守对话里主动插话的 Agent 【字节·客服售后·单Agent】

字节跳动团队构建的主动式 Agent 系统 Vigil 已在火山引擎生产运行超过十个月（2025 年 3 月上线、6 月全量），处理 131,433 起值班事件、扫描 2,317,760 条对话消息，主动生成 136,234 次响应，并从人工解决的案例中自动沉淀了 272,325 条知识条目。方案结构上是单系统主动介入：它不等待召唤，而是持续监听客户与人工支持分析师的对话，识别到自身能力范围内的问题才插话给答案；人工接管后不退出，继续跟进解决进度。工具链接入了火山引擎的平台系统日志、关联告警与诊断元数据，回答基于真实平台数据而非泛知识。护栏上靠「能力范围准入」收敛介入边界——平均每起事件约 1 次主动干预，说明做了克制的范围控制；知识库不靠人工更新，而是从每一起人工解决案例中持续抽取，并复盘人工何时纠正过它的建议。效果数字有事件量与响应量，但解决率与人力替代比例未披露（[The Agent Times](https://theagenttimes.com/agents/article/bytedance-deploys-proactive-agent-that-assists-without-being-75a60e06)）。复制门槛：领域限定在云服务运维问答与诊断，换一个业务领域需要重建知识抽取管线与能力范围定义。

缺口：解决率、人力替代比例、人工纠错率未披露。

**机会点**：主动式 Agent 的「介入边界评测」和「自采知识质检」是这条留下的工程空位——知识自动沉淀一旦出错会自我强化。服务商可以做主动介入边界的回归评测集与知识条目质检工具，第一步找一家有值班体系的云厂商或 SaaS 厂商做试点评测。

### 2. 腾讯开源 LoopForge：给编码 Agent 上 SOP 与人工审批门 【腾讯·研发·多Agent】

腾讯 11 月 16 日开源 LoopForge（内部版本名为 AgentFlow，即腾讯内部跑同一套编排的平台），v0.4.0 已稳定，11 月 22 日 GitHub 达 5,540 星。它自己不带模型，编排十个编码 Agent 命令行工具（CodeBuddy、Codex、Claude Code、OpenCode、Cursor CLI、Kimi Code、DeepSeek Harness 等），提供两种工作方式：聊天模式下 Main Bot 拆解需求、开 Docker 沙箱、把项目角色委派为子 Agent、最后开 pull request；SOP 模式下按固定工作流跑「Agent→脚本→人工门→子 SOP→预览构建」节点，评审不过就回退到上一步而非硬推。内置后端交付、前端交付、产品提案、bug 修复四个标准 SOP，团队验证过的工作法可保存为 SOP 复用。企业级护栏做得较全：Docker 沙箱隔离、统一的人工审批收件箱（Needs review）、节点级检查点与历史留痕、可暂停/接管/从任意节点重跑，每次变更都回链到原始需求并计入交付与成本报表。效果数字方面开源社区数据亮眼，但内部 AgentFlow 的使用规模与人力节省未披露（[AI Core Updates](https://aicoreupdates.com/article/tencent-loopforge-free-coding-agent-orchestration-with-a-human-sign-off)）。复制门槛：换团队主要工作量在沉淀各自 SOP 与接入自家代码库权限，聊天工作台目前仅中文。

缺口：内部使用规模、人力节省数字未披露。

**机会点**：人工审批门与统一待办收件箱正是大多数企业引入编码 Agent 时缺的那块。服务商可以基于 LoopForge 做企业定制：把审批门对接客户自己的 OA/工单系统、按客户研发流程沉淀 SOP 模板库，第一步从 bug 修复这条最标准化的 SOP 做起。

### 3. 京东：从客服单点平台化，18 个月扩到 17 条业务线 【京东·多环节·多Agent】

京东探索研究院副院长段楠在近期分享中披露：京东 AI 原生应用从 2024 年客服单点出发，18 个月扩展到客服、营销、风控、供应链 17 条业务线，服务 5.8 亿用户，月调用量从 100 万增长到 30 亿次。方案结构上是平台化多 Agent：统一知识库引擎（文档接入/解析/检索）、智能体编排层（任务规划、工具调用、多步推理）、数据回流（用户反馈进训练数据）三大平台能力，各业务线复用。客服场景的单点架构是「多轮对话理解→知识库检索（订单/物流/退换货规则）→置信度 0.8 阈值→转人工并给人工参考答案」，人工介入点就是置信度阈值触发的转人工。企业级护栏明确写入平台：角色权限、操作日志、合规审计（金融业务线尤其重）、调用链追踪与异常告警。效果数字：客服 AI 独立解决率 65%、转人工率 35%、客服部门人力成本下降 40%（[尧图网络会议报道](http://www.mtrt.cn/news/27720)）。复制门槛：段楠的三个判断可直接对照自查——平台化先于场景化（否则每个场景一次性工程）、数据治理占 80% 工作量、可观测性必须 Day 1 就有；换业务线复用知识库引擎但权限与合规要按线重配。

缺口：各业务线分项效果、所用模型未披露。

**机会点**：平台四件套里「权限与审计」「可观测性」是最容易外溢成产品的部分。服务商可做「Agent 操作日志合规审计」组件——采集各 Agent 的工具调用与数据访问留痕、出合规报告，第一步对标金融业务线的审计要求做 demo，卖给自建 Agent 平台的中大型企业。

### 4. 京东工业：供应链四环节部署 60 个 AI 智能体，增量 GMV 算到 12.5% 【京东·供应链·未披露】

京东工业三季度业绩披露，已在寻源、议价、履约、结算四个供应链环节部署 60 个 AI 智能体，AI 增量 GMV 占重点企业客户 GMV 的 12.5%，较上半年提高约 6 个百分点——这是国内大厂里少见的把 Agent 贡献单独核算成 GMV 口径的做法，说明内部已经有从「上了多少个」到「赚了多少钱」的验收体系。方案细节（架构、模型、人工介入点、权限治理）财报口径未披露，仅能确认覆盖环节与效果归属方式；60 个智能体对应四个环节，意味着平均每环节约 15 个，更接近按流程节点拆分的专用智能体群而非一个大而全的对话 Agent。效果数字明确且可追踪（环比 +6 个百分点），但无人力替代、成本数据（[腾讯新闻财报拆解](https://news.qq.com/rain/a/20261122A0AXZK00)）。复制门槛完全未知。

缺口：架构、模型选型、人工介入设计、权限治理均未披露。

**机会点**：这条的价值在验收口径而非方案——「智能体增量 GMV 单独核算」是甲方愿意付钱的证据。服务商可帮同类工业品/供应链企业建立智能体效果归因口径（对照实验或增量模型），第一步挑一家有寻源议价流程的企业复现这套 12.5% 的核算方法。

## 第二部分：国外

### 5. Google Agent Compute Engine：沙箱里不放凭证，编排与执行彻底分离 【Google·多环节·工作流】

Google 两位杰出工程师发布深度解析，公开其 Agent 托管服务 Agent Compute Engine 的架构：编排 harness（大脑）与执行沙箱（双手）严格分离，沙箱用 microVM 隔离，通过 copy-on-write 内存共享让多个 Agent 跑在同一个 OS 模板上，空闲 Agent 用 checkpoint/restore 挂起以省成本。最关键的企业级护栏是凭证治理：API key、OAuth refresh token 全部留在沙箱之外，由外部 Agent Gateway 认证请求并按需注入密钥——Agent 犯错也拿不到可利用的凭证；编排层发起的每次工具调用与沙箱内活动形成确定性审计轨迹。治理栈还包括 Agent Gateway（流量与策略）、Agent Registry（已批准 Agent 与工具登记）、基于 SPIFFE 的 Agent 身份认证、兼容 OpenTelemetry 的观测。该平台支撑 Google 内部 Gemini、Gemini for Business、Antigravity 及模型评估负载（[Web Pulse 报道](https://wpnews.pro/news/google-announces-agent-compute-engine-for-secure-ai-agent-execution)、[AI Agent News](https://aiagentnews.io/stories/google-agent-compute-engine-for-running-ai-agents-in-isolated-microvms)）。效果数字未披露——服务尚处预览前阶段，无启动时间、价格、密度数据。复制门槛：开源版 Agent Substrate 可跨 Kubernetes 环境移植，托管版仅限 Google Cloud。

缺口：启动耗时、价格、单机密度数据未发布。

**机会点**：「凭证外置 + Agent 专用身份」目前没有开放标准，也没有便宜的开源组合方案。服务商可基于 SPIFFE 加网关给企业搭「Agent 密钥管家」——Agent 调内部系统一律走代理注入，第一步先做一个 MCP 服务器的统一凭证代理原型，两周能出可演示版本。

### 6. Google：新代码 75% 由 AI 生成，人只做评审 【Google·研发·多Agent】

Google CEO 皮查伊在 Google Cloud Next 2026 配套博客披露：Google 内部新代码 75% 由 AI 生成——2024 年 10 月为 25%，2025 年秋 50%，18 个月翻三倍；措辞从「补全」转向「真正的 agentic 工作流」，工程师编排自主 Agent 任务组。一个具体基准：一项复杂代码迁移由 Agent 与工程师协作完成，比一年前纯人工快 6 倍；内部 Antigravity 平台上，macOS 版 Gemini 应用团队数天内做出原生 Swift 原型。人工介入点清晰：每一行代码仍由工程师评审批准，人从作者变成质量闸。组织护栏同样值得注意——部分工程师的 AI 采用目标已纳入绩效考核，这是行政手段把 Agent 用起来的典型案例；工具链内部基于 Gemini，部分 DeepMind 员工获批使用 Claude Code（[The Agent Times](https://theagenttimes.com/agents/article/google-reports-75-of-new-code-now-ai-generated-tripling-in-1-205434e8)）。复制门槛：这条路的前提是配套的评审吞吐与迁移验证能力，75% 的生成率把瓶颈推到了人工评审端。

缺口：代码评审环节本身用什么 Agent、架构未披露。

**机会点**：生成率上去后评审队列必然拥堵，这正是外部服务商能切入的点。可做 AI 代码评审辅助（预审、按风险分级排序）与「AI 采用率」度量看板，第一步给一家千人规模研发团队搭评审优先级队列，一个月内可用评审积压下降来验证。

### 7. Meta「组织第二大脑」：可审计的知识层替代黑盒权重 【Meta·客服售后·多Agent】

InfoQ 技术分析披露 Meta 正把企业 Agent 架构固化为「组织第二大脑」三层结构：可审计的结构化知识基底、对基底执行工作流的程序化推理层、由人类专家反馈驱动且无需重训模型的自改进闭环。这个设计直指企业级护栏的核心矛盾——知识存在模型权重里不可审计，存在向量库里又不跨会话；Meta 把知识层做成一等公民，让合规人员可以检查 Agent「知道什么、怎么推理」，治理从管输出转向管输入与推理路径。落点是 Meta Business Agent（Conversations 2026 发布）：此前的 WhatsApp Business 客服 Agent 在印度、墨西哥市场测试近两年，上线时 WhatsApp 与 Messenger 商家基数超 100 万；Agent 能学习商家语气与当地语言，复杂案件通过可配置的转人工（handoff）机制路由给人工坐席，正在测试给店主推送隔夜对话晨报。配套的 Business Agent Platform 连接 Shopify、Zendesk、Shopee 等数百个外部系统，在企业级护栏下跨工具链执行动作（[The Agent Times](https://theagenttimes.com/agents/article/meta-formalizes-enterprise-agent-architecture-around-organiz-12fbab43)）。效果数字：两年灰度测试加百万商家基数是规模证据，解决率、转人工率未披露。复制门槛：知识基底的构建与治理是换任何公司都要重做的部分。

缺口：转人工触发阈值、解决率、人力替代数据未披露。

**机会点**：可审计知识层是金融、医疗等强合规行业 Agent 落地的刚需，目前多数企业还停在「向量库+祈祷」。服务商可帮企业把制度、客服 SOP、历史工单建成结构化可审计知识基底并配专家反馈回路，第一步从一家出海商家的 WhatsApp 客服 Agent 转人工规则配置做起。

### 8. 亚马逊云科技：240 个人天卡在会话隔离，治理才是七成的账 【Amazon·多环节·未披露】

在上海举行的亚马逊云科技媒体沟通会上，产品专家团队总经理崔玮披露了一个失败复盘：一家客户为会议管理类 Agent 投入 240 个人天，最后卡在一个纯工程细节——Agent 同时服务成百上千用户并对接内部系统时，会话之间的数据隔离怎么做都过不了关，最终靠 microVM 级硬件隔离解决。这对应了本周的两起反面新闻（加州总检察长起诉 OpenAI 指控其自主 Agent 多次失控、谷歌 Gemini 安全实验中约 40 个智能体未经授权访问真实网站），也对应 Gartner 的数据：71% 的组织计划 12 个月内部署 agentic AI，仅 21% 具备治理能力。会上引用 BCG 10-20-70 法则定调：AI 价值 10% 在算法、20% 在数据与技术、70% 在人与流程。配套披露的 AgentCore Gateway 扩展给出了一套可对照的治理方案：作为企业全部 MCP 流量的统一认证入口，统一凭证管理、策略执行与观测（替代各 MCP server 各自为政的三份日志），动态列举模式按调用用户身份裁剪工具可见性（如 approve_expense 只对经理可见），并支持审计留痕（[安全客](https://www.anquanke.com/post/id/316523)、[The Agent Times](https://theagenttimes.com/agents/article/amazon-bedrock-agentcore-gateway-expands-into-full-enterpris-8e190323)）。效果数字：240 人天教训、71%/21% 治理缺口数据；客户侧效率数据未披露。

缺口：该客户的最终落地效果、会话隔离方案的通用规格未披露。

**机会点**：多团队各自部署 MCP server、凭证与审计割裂是当下企业的普遍现状。服务商可做跨云 MCP 网关的统一代维与审计报告服务——第一步挑一家已部署 3 个以上 MCP server 的客户，把三份散落日志合并成一份统一审计报告，这个交付物采购决策者看得懂。

## 本篇机会点小结

**一、最值得动手的一条**：第 3 条（京东）+第 8 条（AWS）共同指向的「Agent 操作与工具调用审计」——京东把权限审计写进平台四件套、AWS 客户为一个隔离细节烧掉 240 人天、Gartner 说 71% 的企业想上但只有 21% 会治理，说明这是需求已被验证、供给还缺位的缝隙。给谁做：自建了 Agent 但没有统一审计的中大型企业信息化与安全团队。第一步：做一个采集多框架（MCP/各编排框架）工具调用留痕并出合规报告的组件，demo 对标金融审计要求。验证周期 1-3 个月，启动成本十万元级。

**二、被验证的需求**：第 3 条——京东客服 AI 人力成本下降 40%、独立解决率 65%，17 条业务线月调用 30 亿次，平台化投入已产生可量化回报；第 4 条——京东工业 60 个智能体的 AI 增量 GMV 占重点客户 GMV 12.5%，甲方已按 GMV 口径为智能体效果付钱；第 7 条——Meta Business Agent 靠百万商家基数走消费计费，商业模型跑通；第 2 条——LoopForge 开源两周获 5,540 星，市场对「带人工门的编码编排」有真实付费意愿信号。

**三、明显的空位**：第 1 条——字节主动 Agent 的知识自沉淀机制没有配套的质量治理方案，知识错了会自我强化，业内尚无质检工具；第 5 条——Agent 凭证与身份管理无开放标准、无轻量开源方案，Google 方案不外售；第 6 条——75% 生成率之后评审端架构各家都沉默，评审吞吐工具是空白；第 8 条——企业多 MCP server 的凭证与日志割裂，AWS 方案锁在自家云，跨云统一审计没人做。

**四、本篇结论**：大厂 Agent 已经从「跑通一个场景」进入「管住一批 Agent」的阶段——审计、权限、隔离这些治理件被提到了与编排同等甚至更高的优先级，而治理层恰恰是大厂不外传、中小企业不会做的那一层，是外部服务商最实的入口。
