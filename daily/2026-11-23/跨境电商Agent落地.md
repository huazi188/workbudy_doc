## 第一部分：国内

### 1. 连连数字发布 XWorker：智能体编排+智能体钱包双护栏 【整链路·多市场·多平台】

连连数字 11 月 19 日在新加坡金融科技节发布 AI 数字员工平台 LianLian XWorker，面向跨境电商卖家：企业提出市场拓展目标后，平台拆解任务并调度多个专业智能体，覆盖市场与竞品分析、Listing 制作、SEO、多语言本地化、广告运营，后续延伸到采购履约、客户服务、多店铺对账与回款资金协同。结构上属于多智能体编排平台，通过开放能力市场连接第三方智能体、业务连接器与 ERP、电商数据平台等系统，任务在 7×24 小时云端环境离线推进，需要人工时提醒确认。工具链上，智枢 RouterBrain 已接入 300 余款模型做智能路由与 Token 成本管理；跨境特有的护栏做在金融层——智能体钱包按交易场景设单笔额度与累计预算，支付走一次性令牌，智能体不接触真实卡号，XCard 支持 140 余种货币、120 余类支付场景。效果数字：无效果数据（发布稿无落地案例数据）。复制门槛：连连自有 68 项支付牌照覆盖 200 多个国家和地区，金融侧加国家成本低，但电商侧每接一个 ERP 或平台都要逐个开发连接器，这是加国家的主要重做项（[来源](https://ex.chinadaily.com.cn/exchange/partners/82/rss/channel/cn/columns/sz8srm/stories/WS6b03a916e4b0e14252fccb25.html)）。

**机会点**：连连的能力市场缺第三方业务连接器，懂跨境 ERP 生态的团队可为马帮、店小秘等做连接器上架抽成，第一步选一款用户量大的 ERP 做双向同步验证。

### 2. GLM-4.7 + Claude Code Skill：海外仓补货调拨三件套 【物流履约·多市场·未披露】

一篇工程实践文章拆解了用 GLM-4.7 加 Claude Code Skill 搭海外仓补货 Agent 的做法：客户有 3000+ SKU、分布在 5 个海外仓，运营此前每天看 10+ 张表格手动算补货与调拨，平均耗时 3.5 小时。方案由三个 Skill 组成——按 SKU 取日销数据、算补货点与安全库存、输出各仓调拨计划 JSON，属于工作流式单 Agent 多技能结构。跨境护栏有两处硬约束：取数不直连数据库而是走客户已有 REST API（该 API 有 99.95% 可用性 SLA）；补货公式不写死，把基础框架给模型，按销量波动系数（CV 值）动态调安全库存，适配快消峰谷。人工介入点文中未披露。效果数字：无效果数据（文中 3.5 小时是改造前的基线，未给出改造后数字）。复制门槛：换一家客户要重接其 ERP/库存 API，公式框架可复用；文未涉及多语言与汇率，卡点是每家客户的库存数据接口各不相同（[来源](http://www.hqwc.cn/news/5516.html)）。

**机会点**：这三个 Skill 已接近可复制的标准件，稍作封装就能卖给多仓铺货卖家，第一步找一个用店小秘或领星的多仓客户把 Skill 接到其开放 API 上跑通。

### 3. 货叮咚 ERP：TikTok Shop 多国一键刊登 + MCP 智能体入口 【多平台矩阵·多市场·TikTok Shop】

邦阅网 11 月 23 日刊发的产品能力详解显示，货叮咚 ERP（广州亦麦）面向 TikTok Shop、Shopee、美客多、Coupang 四大平台的东南亚、拉美、日韩市场，单账号集中管理多店，兼容跨境店、本土店、全托管店型。跨境环节的自动化做得很细：TikTok 同款商品一键发布多个国家站点并分站点独立定价；定时发布设单店每日上新上限以规避平台接口限流、适配跨境时差；Shopee SKU 5 倍/7 倍价差超限在认领阶段自动处理，减少发布报错；侵权违规检测覆盖品牌 Logo、IP 版权、外观专利、违禁词等六大模块，上架前筛查。结构上是 ERP 内置 AI 能力加 MCP 开放平台——可对接豆包、扣子等智能体用自然语言查经营数据，广告预警推送钉钉、企业微信、飞书。仓储侧支持海外多国多仓的入仓到出库全流程与双模式库存预警（固定阈值/可售天数）。效果数字：无效果数据（产品介绍稿）。复制门槛：其平台适配是逐平台手工磨出来的（如 Shopee 24 小时活动间隔的特殊适配），且明确暂未覆盖亚马逊与独立站，加一个平台要重做一轮接口与规则适配（[来源](https://www.52by.com/article/244257)）。

**机会点**：它把最难磨的平台规则适配做完了但只覆盖四平台，对以亚马逊为主的公司存在补位空间，第一步是给同时做亚马逊+TikTok 的卖家做两边库存与刊登的桥接工具。

### 4. CaptainAI：Ozon 俄语 Listing、EAC 合规与物流商比价方案 【多语言内容·欧洲·未披露】

CaptainAI 连发多篇 Ozon 俄罗斯市场方案，围绕中国卖家三大坎：俄语本地化、合规、物流。多语言侧：中文描述翻俄语并适配 Ozon 标题 80 字符等字段格式，输出关键词密度与可读性评分；图片侧自动去中文水印生成 Ozon 合规白底图。合规侧内置俄罗斯税务法规库（宣称收录政策与法条超 10 万条），实时预警质控订单罚款、关键词重复罚款等风险，有卖家因未标注材质被罚款后系统自动生成合规标签模板；EAC 认证缺失会在上架前预警。物流履约侧按体积重量目的地对比 Ozon 官方物流与 CDEK、Boxberry 等第三方报价，案例数字：切换货代后莫斯科配送时效从 15 天缩到 8 天、运费降 18%；黑五提前 45 天提醒备货、避免断货损失超 50 万卢布；切换履约模式物流成本降 12%、单件利润提升 23%。结构上是单平台全流程工具，人工介入点未披露。复制门槛：整个方案押注俄罗斯单一市场的法规库与物流商网络，这套合规库换一个国家全部重做——这既是壁垒也是它出不了俄语区的原因（[来源](http://aicaptan.com/article/ecommerce/9252)）。

**机会点**：EAC 认证与诚信标签类目的校验逻辑是可独立抽取的资产，做一份俄语区强制认证清单加 API 校验服务，先卖给做 Ozon/Wildberries 的铺货卖家试水。

## 第二部分：国外

### 5. 亚马逊 Selling Partner 插件 + Ads MCP：库存-广告联动与确认护栏 【物流履约·北美·亚马逊】

Gate News 11 月 21 日详述亚马逊两个官方 Agent 接口的联动用法：Selling Partner 插件（beta，目前限美国站）把 AWS Quick、Claude 等 AI 助手连到 Seller Central 的 listing、库存与销售数据；Ads MCP Server（2026 年 2 月起开放测试）通过 Marketing Stream V2 在大促日每 15 分钟刷新 ACOS/ROAS。典型跨境履约工作流：Agent 发现广告主力 ASIN 中有 5 个库存不足 10 天，建议暂停其广告并把预算挪给库存 45 天以上的高毛利 ASIN，卖家确认后执行。护栏全部围绕跨境误操作设计：两套工具各自独立 OAuth 授权（Merchant Token 与 Profile ID 两套身份）、提示词明令「数据拿不到就直说、不许估」（商品成本、竞品价、供应商交期都不在数据范围内）、所有改预算停投动作必须人工确认、大促关键决策与实时后台交叉核对。全球卖家 12 月 31 日前可领 12 个月免费 AWS Quick Plus 加 10 个子账号。效果数字：早期测试者称省时但无量化数据。复制门槛：加一个站点要看插件覆盖范围——目前仅美国站 beta，多站点协同尚未放开，这是明确缺口（[来源](https://www.gateex.org/news/detail/amazon-selling-partner-plugin-and-ads-mcp-server-enable-ai-driven-holiday-25762432)）。

**机会点**：官方把接口铺好了但护栏 SOP 要卖家自己写，把双 OAuth 配置、库存阈值-广告联动规则、防幻觉提示词打包成多站点通用模板包，先在卖家社群免费分发测需求。

### 6. Shopify Markets 多语言购物车本地化：七项决策与六语言测试矩阵 【多语言内容·多市场·独立站】

Cartylabs 11 月 21 日的工程指南指出：2026 年增长最快的 Shopify 店铺普遍卖 5-15 个国家，而收入漏损集中在购物车——平台层（Markets）管了货币、域名、税费，购物车抽屉、加购推荐、赠品逻辑全靠应用自己本地化，做错的店铺在非英语市场漏 5-15% 转化率。方案给出七项必须逐市场配置的决策：货币格式、购物车文案语言、各市场原生免邮门槛（美国 75 美元不能直接换算成欧元区 69 欧元这种「怪美国数字」）、各市场赠品、按市场过滤的推荐目录（只推荐该市场有货有价的变体）、税含/不含税展示、RTL 布局（阿拉伯语/希伯来语需镜像布局加 CSS 逻辑属性）。工程细节扎实：16 种语言 200KB 翻译包改为请求时按语言服务端内联，压到每语言 12KB；六语言最小测试矩阵（德语长词断版、日语无空格、阿语 RTL、西语倒问号）不需要母语审校即可查出高产 bug。合规侧建议年销 500 万美元以下用 DIY 配置覆盖 90% 价值，10+ 国复杂 VAT/IOSS 才上 Markets Pro（Merchant of Record）。效果数字：转化率漏损 5-15%（反向）、包体 200KB→12KB。人工介入点与 Agent 编排未披露——这是工程实践而非完整 Agent 方案。复制门槛：加一个国家=加一个语言 JSON 文件+一条免邮门槛配置+进测试矩阵，是八条里复制成本最低的（[来源](https://cartylabs.com/blog/shopify-markets-cart-localization)）。

**机会点**：六语言测试矩阵可直接产品化成自动化体检服务，第一步给 DTC 品牌多国站跑一遍购物车全流程并出漏损报告，免费体检引流再卖修复。

### 7. CodeHTS：HS 编码 AI 分类四段校验管线，置信度不足转报关行复核 【合规税务·多市场·多平台】

CodeHTS（合规工具站，页面 11 月 21 日更新）把关税编码分类做成了带审计的 Agent 管线：推理模型从商品描述提 10 位编码并给出 GRI 归类依据，随后与官方 USITC HTS 2026 向量库比对（要求余弦相似度 ≥0.78），再由无 AI 的规则引擎确定叠加 MFN 税率、301 条款加征与 USMCA 优惠，最后写入防篡改审计日志（记录用户、模型版本、源数据哈希）。跨境护栏明确：综合置信度 ≥70 才自动确认，否则转持牌报关行人工复核；导出 PDF 供报关行审核。数据源直接对齐各国官方税则（美、欧 TARIC、英、加、澳、新加坡六个关税区，17000+ 编码），落地成本含 0.3464% 的 MPF 与 0.125% 的 HMF。对接跨境系统：亚马逊卖家 feed 自动分类每个 ASIN、Shopify、WooCommerce、QuickBooks、SAP 均有连接器，另有 REST API 与 webhook。效果数字：平均分类置信度 94%、平均约 3 秒、Pro 级进口商月均节省有宣称但未给具体金额。复制门槛：扩一个关税区要接该国官方税则库并维护规则引擎，301 清单与反倾销令逐个跟进——数据维护是持续成本，对接层（REST API）已标准化（[来源](http://codehts.com/)）。

**机会点**：它只覆盖六个关税区且面向美国合规团队，做中东、东南亚、拉美税则的同类管线尚无人做，但更现实的第一步是借其 REST API 为已有存量 SKU 错码的卖家做一次全量编码治理。

### 8. ngini Seller Studio：一次上传按平台导出合规素材套件 【多平台矩阵·北美·多平台】

ngini 的对比页（11 月 23 日更新）给出跨平台素材工作流的解法：中小卖家同时跑 Shopify 独立站、TikTok Shop、Etsy、Amazon Handmade 时，每个平台的图片规格、文案调性与政策要求都不同，而 Shopify Magic 只在 Shopify 后台生效。ngini Seller Studio 从一次上传导出各平台发布就绪套件：TikTok Shop 9:16 与 1:1、Shopify 1:1 与 4:5、Etsy 4:5 并自动打 AI 披露元数据、Amazon Handmade 1:1 白底合规预设，图片风格跨平台一致、文案按平台调性改写。合规是核心卖点：Etsy 的 AI 披露政策是 2026 年最缺工具的合规事件——仅一季度就下架 1.2 万条 listing。定价 19-99 美元/月，年付七折，Growth 档有变体批量生成。跨境护栏是平台级的：AI 披露元数据自动标注、白底合规预设直接规避下架。效果数字：无效果数据（合规下架数字是行业背景而非客户效果）。缺口：多语言翻译与多国站点定价能力未披露，目前以美国平台合规为主，跨境多语言是空档（[来源](https://ngini.com/en-us/compare/shopify-magic-vs-ngini-seller-studio)）。

**机会点**：各平台的 AI 内容披露政策（Etsy 已罚、亚马逊欧盟区在路上）正在批量产生合规标注需求，第一步做一个 Etsy AI 披露自动标注的小工具，吃政策窗口期的下架恐慌。

- 第 4 条：缺口：人工介入点、法规库更新频率与准确率未披露
- 第 5 条：缺口：美国站以外的站点支持时间、量化提效数据未披露
- 第 6 条：缺口：Agent 编排方式未披露（工程实践为主）
- 第 7 条：缺口：定价、月均节省具体金额、客户数未披露
- 第 8 条：缺口：多语言与多国定价能力、客户效果数据未披露

## 本篇机会点小结

**一、最值得动手的一条**：第 2 条的海外仓补货调拨 Skill。它是本篇唯一一条架构、参数、数据接口全部公开到可以直接开工的方案——三个 Skill、走客户已有 REST API、公式按销量波动动态调参，给谁做很明确（多仓铺货卖家），第一步找一个用店小秘/领星的多仓客户接到其开放 API 跑通，两到四周就能用「补货建议采纳率」验证；千元级启动成本是八条里最低的，且补货调拨是卖家每天都要碰的高频痛感。

**二、被验证的需求**：第 4 条显示俄语区卖家已在为合规买单——避免断货损失 50 万卢布、物流成本降 12% 的案例来自真实使用；第 8 条的 Etsy AI 披露政策一季度下架 1.2 万条 listing，说明平台合规标注是刚性且付费的；第 6 条的 5-15% 转化率漏损是多语言购物车的量化需求证据；第 1 条连连为此专门发了产品线，说明跨境支付大厂判断智能体执行层已有真实交易需求（已跑通 Visa 智能体目录的真实采购交易）。

**三、明显的空位**：第 5 条亚马逊官方接口目前只有美国站 beta，多站点协同（欧洲、日本站的库存-广告联动）没有官方方案，服务商可先补；第 3 条货叮咚明确不做亚马逊和独立站，两套生态之间的桥接没人做；第 7 条 CodeHTS 只覆盖六个关税区，中东、东南亚、拉美的 HS 编码自动分类仍是空白；第 8 条 ngini 有平台合规预设但没有多语言，多语言×平台合规的交叉点没人占。

**四、本篇结论**：跨境 Agent 正在从「会生成」走向「敢执行」，而敢执行的分水岭是护栏是否做成系统硬约束——支付额度（第 1 条）、编码置信度阈值（第 7 条）、库存阈值触发（第 5 条）都已代码化；但加国家要重做的老问题一点没变：合规库逐国建、平台适配逐个磨、物流商逐家接，这三处重做成本就是今天最清晰的生意入口。
