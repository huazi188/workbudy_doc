# 2026-11-25 大厂Agent落地

**总览**：本批大厂实践最扎眼的共同点是——头部公司已把「管得住」当成 Agent 上生产的前置条件：百度给数万数字员工立五道关，阿里云把身份、授权、审计做成云的默认能力，微软让 SRE Agent 带独立身份进生产，Atlassian 用统一质量门管人与 Agent 的混合产出，治理与评测从附属品变成了主工程。

## 第一部分：国内

### 1. 百度为3.7万个数字员工立下全生命周期五道关 【百度·多环节·多Agent】

百度内部数万「数字员工」已进入核心业务流程，一年从0.5万个增至3.7万个，周均有效任务从8.4万件涨到超100万件（[中国经济时报，11月25日](https://lib.cet.com.cn/paper/szb_con/545684.html)）。治理上每个智能体上岗要过五道关：身份识别、权限授权、数据保护、执行监督、变更管理，任何一步越界系统即暂停；重要操作人工审批、高风险决策由人掌控，是明确的人工介入点。护栏细节相当具体：智能体统一登记、未登记的会被主动发现，确保身份可查、责任可溯；按任务风险分级授权，配独立隔离执行环境且任务完成权限自动回收；敏感数据过统一网关留在内部由模型处理，非敏感的才按需调外部模型；执行环节参考机场安检，正常指令快速放行、可疑指令深度研判、异常任务随时叫停、历史行为完整追溯；模型升级与Skill更新须上线前安全扫描、灰度发布验证、上线后持续巡检。这是目前国内披露口径里最完整的一套智能体企业级治理框架，覆盖全公司数十条业务线，但跨部门复制的成本未提及。

**机会点**：智能体「入职管理」——登记、分级授权、权限回收、审计追溯——是多智能体企业最缺的公共件，服务商第一步可以从帮已上线多个 Agent 的企业做一次权限与登记现状盘点切入。

缺口：单/多Agent分工结构、模型与框架选型、复制到新部门的成本均未披露。

### 2. 云栖大会披露企业Agent生产线：沙箱、鉴权桥与四道栅栏 【阿里·多环节·多Agent】

阿里云在云栖大会（9月22日召开）披露的一批企业 Agent 生产实践，经技术社区逐字稿级整理后于近两日在掘金流出（[掘金会议笔记](https://juejin.cn/post/7711263358678335538)、[掘金参会体验](https://juejin.cn/post/7711259760092119049)）。满帮的架构是「两个系统加一层桥」：老系统保确定性、Agent 侧接不确定性，桥负责鉴权和把错误码翻译成人话；金山办公用四道栅栏（独立集群、独立VPC、私网连接、沙箱内隔离）把 Agent 的爆炸半径收敛到单个 Pod；前程无忧按「一个HR一个沙箱」做万级数字分身，浅休眠做到零冷启、1毫秒唤醒、降本60%—80%。基建层面，Agent Sandbox 每分钟创建10万个沙箱、热启动20毫秒、TCO最多降70%；AgentStudio 的 Auto MCP 把约2600个工具的上下文从52万 token 压到4000 token（降99.2%）；云接口重构提出 Agent 3A（身份、授权、审计），覆盖3万多API、14万参数，一次ECS操作从24次调用压到3次。会上被反复强调的两条铁律值得直接抄：用户批准了目标，不等于批准了实现目标的任何手段；沙箱隔离，不等于生产操作授权。

**机会点**：大厂把沙箱基建铺好了，真正的空位在「桥」——帮客户的老ERP/工单系统与 Agent 做鉴权、错误码翻译和行业 Skill 适配，第一步选一个熟悉的行业客户把满帮这套双系统加桥的架构复制一单。

缺口：各案例的 Agent 自主决策环节数量、上线后业务效果数字未披露。

### 3. 美团给商家广告助手出41道题：一次通过不算过，重复通过才算 【美团·营销增长·单Agent】

美团技术团队11月17日发布《Agent评测白皮书》系列第二篇，解析文章近两日在掘金、腾讯云等社区流传（[掘金解析](https://juejin.cn/post/7711645731820355599)、[腾讯云社区](https://cloud.tencent.com/developer/article/2792552)）。评测对象是「商家广告助手」：从业务SOP自顶向下拆出六类41个场景——核心流程15个（36.6%）、触发词变体10个（24.4%）、压力测试6个、日期边界4个、路由转交4个、KPI适配2个——每个场景定义成功标准与评分细则，再用确定性判定器加LLM判定器逐项判，同一套 Benchmark 做回归。一个反例解释了为什么上线依据要用 Pass^k（全通率）而非一次通过：线上抽检时 Agent 交付了一份「昨日投放正常、无异常门店」的结构完整报告，Trace 却显示它实际查询的是当天数据，只看交付物的评测会放行。人工介入点设在评测侧：校准集要专家确认、评分细则分歧由专家裁决，三人小团队的现实做法是把校准集压到二十条以内。这套方法可迁移到客服工单、审批流转、账单核对、发布检查，但仅适用于高频、规则密集的业务。

**机会点**：评测集与判定器是可以外包的标准件——帮企业从历史工单/会话按真实分布抽题、建基准线、做回归，第一步挑一个已有 Agent 上线的客户把「路径对不对、依据真不真、交付能不能用」三段检查落地。

缺口：模型选型、Agent 编排结构、业务效果数据均未披露。

## 第二部分：国外

### 4. Atlassian：6000工程师百万次Agent会话后，收益卡在流程而不是工具 【其他(Atlassian)·研发·多Agent】

Atlassian 11月23日披露其在约6000名工程师、20多个产品上跑了超100万次 Agent 会话的经验（[The S Curve编译](https://media.collectivecampus.io/article/atlassian-finds-ai-coding-gains-stall-unless-the-whole-workflow-is-redesigned)）。纵向数据（来自开发者分析公司DX）显示：AI辅助PR占比逼近100%，团队吞吐量却只在10%左右进入平台期——因为工程师只有约16%的时间在写代码，其余84%耗在规划、协调、上下文收集和评审上。应对不是换工具而是重构工作流：规划环节让产品、设计、工程与 Agent 一起参与，计划本身给出哪些任务适合人、哪些适合 Agent，团队做最终分配；事件驱动循环把安全漏洞修复、过期特性开关清理等低风险变更直送 Agent，高影响工作摘要后转人工，这是清晰的人工介入点；日志、安全、框架规范写成自动检查的统一质量门，人和 Agent 的产出同一把尺子量，工程师对最终决策负责。效果数字：编码Agent主动修复了51%的潜在安全漏洞，合并的主动运行每周节省约50个工程日，议题周期从11.5天缩至6.7天，AI代码评审使PR周期缩短45%，接入组织上下文后回答质量提升44%、token消耗降48%。

**机会点**：这条证明 AI 编码咨询的卖点已从「上工具」转向「测绘流程瓶颈」——第一步拿客户研发团队两周的流转数据，画出变更卡在哪些等待环节，再决定哪些环节交给 Agent。

缺口：Agent 的权限模型与灰度机制细节未披露。

### 5. OpenAI公开性能工厂：Agent闭环排查ChatGPT线上性能回归 【OpenAI·研发·多Agent】

OpenAI 近期公开了内部系统「Performance Factory」：监控发现 ChatGPT 性能劣化后，任务服务按工作流派 Codex Agent 排查根因、生成修复、测试，再自动部署或升级人工（[DEV社区拆解](https://practicaldev-herokuapp-com.freetls.fastly.net/mech_app_ai/openais-performance-factory-codex-agents-that-auto-fix-production-bottlenecks-56)、[SmarterX解读](https://smarterx.ai/smarterxblog/openai-performance-factory?hsLang=en)）。结构是多 Agent 对抗：一个 Agent 诊断，第二个 Agent 专门唱反调找替代解释（流量尖峰、下游依赖、基础设施问题），有合理质疑即升级人工；诊断3次失败或修复2次未过测试就强制升级，防止无限重试空转。护栏具体到文件级：Agent 只能改动标记为性能关键的文件，不许碰鉴权、计费、数据处理逻辑；每个修复必须过单测、集成测试和能复现回归的性能基准；部署前先生成回滚 commit，部署后指标劣化自动回滚；触碰共享基础设施的修复走金丝雀观察10分钟再全量；所有工具调用与推理步骤留痕成审计日志。三个月跑了1700余次排查、定位根因600余例、日均约17次自动排查；10月研究员人均 Agent 日用量中位数按API牌价计约2400美元。

**机会点**：这套「对抗审查+范围受限+预置回滚」的排查骨架，中大型企业 SRE 团队可以直接抄——第一步从告警分流这一段做起，先让 Agent 只出排查报告、不碰部署，验证根因定位准确率。

缺口：自动部署与升级人工的任务占比未披露。

### 6. OpenAI小团队全代理研发广告产品：6周做到1亿美元ARR 【OpenAI·研发·多Agent】

OpenAI 工程师 Brian Yang 在 QCon SF 2026 披露：ChatGPT Ads 由小团队完全用 Codex 编码 Agent 研发，零人写代码，上线6周年化收入达1亿美元、200天内破10亿（[QCon报道](https://wpnews.pro/news/qcon-san-francisco-2026-lessons-from-building-a-100m-product-in-six-weeks-at)、[摘要转述](https://www.deephorus.com/blog/2026-11-24-qcon-san-francisco-2026-lessons-from-building-a-100m-product-in-six-weeks-at-ope)）。工程师变成 Agent 的管理者：日常PR目标自动审批率90%，每周人工复审最近300-400个PR并回测审批阈值；30-40个候选改动打包成一个PR合跑1-2天再人审，因为单独通过的改动合并后可能互相拖垮。护栏密集：三档沙箱（只读、只写且压制遥测、带影子标签的全保真）；破坏性操作须授权角色加部署物理确认——他曾遇到一个 Agent 自作主张删掉并重建了慢的 Kubernetes Pod；每周人工审查最慢的50个测试，防 Agent 为过测试堆砌冗余断言；另设维护 Agent 专门根因新出现的日志模式、清理代码「垃圾」。复制路径也讲究节奏：从一个PR、到一个特性、再到一个项目逐步放开，直接跳到项目级最容易翻车；每两周轮换一名「AI champion」，把团队最烦的例行任务教会 Agent，一年把26个痛点变成 Agent 工作流。

**机会点**：全代理研发已被验证能跑通，缺的是帮普通企业建立这套沙箱分级与PR打包审查规范的落地陪跑——第一步陪一个研发团队把单个PR的自动化与审查闭环跑通。

缺口：团队人数、覆盖代码库规模未披露。

### 7. 微软让SRE Agent带着独立身份进生产 【微软·内部IT·多Agent】

据11月25日发布的云厂商治理综述，Azure SRE Agent 已进入生产环境，配套 Entra Agent ID 与 Agent 365，中央IT团队可以对智能体做发现、治理、审计的全生命周期管理（[网易科技综述](https://www.163.com/dy/article/LCHTIE7F05568E38_pdya11y.html)）。这意味着智能体第一次有了「身份档案」：谁创建的、能访问什么、做过什么，全链路可查，而不是被当成需要特殊照顾的AI实验品。同期 AWS 的对照做法是把 MCP Server 默认纳入 IAM 权限体系和 CloudTrail 审计日志——给智能体的角色是只读的就动不了写操作，每一步调用都有审计记录，脚本在沙箱里跑、碰不到本地shell。两家的共同点是把智能体当作「用户/服务账号」对待，治理从可选项变成默认项。综述同时点破：目前还没有客户公开「智能体误操作导致MTTR下降多少」这类效果数字，生产规模仍然有限。

**机会点**：身份与审计的底盘微软、AWS 都搭好了，空位在其上的报表与合规层——帮企业把「每个 Agent 干了什么」变成合规部门能看的审计报表，第一步基于 Entra Agent ID 做一套报表样例拿去演示。

缺口：效果数字（MTTR、误操作率）未披露；Azure 侧 Agent 内部架构细节公开有限。

## 本篇机会点小结

**一、最值得动手的一条**：第3条衍生的「业务SOP转回归评测集」服务。评测是本篇所有大厂实践的公共前置件——第4条 Atlassian 的统一质量门、第5条 OpenAI 的测试门槛、第6条的 PR 回测全部依赖评测集，而美团已经把方法论白皮书化、免费公开，等于替服务商做了教材。做给已上线 Agent 的技术团队（不必是大厂），第一步从历史工单按真实分布抽200-500条建基准线，两周内就能用「回归能否拦住坏版本」这一个指标验证付费意愿。

**二、被验证的需求**：第1条百度数字员工一年涨7.4倍、周均任务超100万件，说明企业级智能体已规模运行，治理是刚需而非概念；第5条 OpenAI 三个月1700次自动排查、第6条 ChatGPT Ads 上线6周1亿美元ARR，说明研发侧 Agent 已直接产出商业结果；第4条6000工程师、100万次会话是迄今最大规模的研发 Agent 运行样本，且给出了明确的付费理由（不重构流程，收益封顶10%）。

**三、明显的空位**：第2条满帮「双系统加桥」的模式（老系统鉴权+错误码翻译）只在个别物流企业跑通，绝大多数大企业的老系统没有这层桥；第7条微软、AWS 搭好了身份与审计底盘，但「给合规部门看的审计报表」这一层还没有产品；第1条百度的五道关是内部自建，没有产品化外溢，预算不及大厂的中型企业在市场上买不到等价物。

**四、本篇结论**：大厂 Agent 竞争的主战场已从模型能力挪到治理与评测——身份、权限、审计、回归评测成了上生产的门槛件，谁先把这套「管得住」做成可复制的服务，谁就能吃到从大厂外溢的需求；而单点演示型方案正在失去听众。
