# 2026-11-25 工厂Agent落地

**总览**：今天这批方案共同点高度一致——工厂 Agent 的可信度不押在模型上，押在写权限护栏上：Agent 只提议，确定性代码做约束校验，数字孪生或历史案例验证通过后，写操作仍由人工签发，谁先把这层做成标准件谁拿走生意。

## 第一部分：国内

### 1. LangGraph 三智能体车间复盘：设备诊断+排产+质检一套编排 【排产调整·注塑·多Agent】

一线工程师在注塑等车间场景落地的多智能体项目完整复盘（11月24日发布）。原来这类事靠老师傅凭经验排查、Excel 排产。方案结构：三个智能体——设备故障诊断、生产排程辅助、质量缺陷分析——由 LangGraph StateGraph 做顶层编排，插单、设备报警、质量异常事件触发自动路由；排程内部再拆四个角色（订单解析、产能评估、排程优化、异常处理），全局状态与局部状态分层防覆盖。人工介入点在写操作：改工艺参数、下发控制指令、改订单状态一律只生成审批单，由指定负责人在 MES 里确认执行，读操作全自动。工具链：LangChain+LangGraph 为主、Dify 只做原型，私有化 Qwen2.5-72B（vLLM/Ollama 起兼容接口）、Mem0 长期记忆、FAISS 向量库；MES 走 HTTP 接口加签名认证的工具函数并做字段约简（只留 3-5 个指标），SCADA/PLC 走 OPC UA 网关，自研 SPC 与视觉模型用 tool 装饰器封装成智能体的工具。护栏是幻觉三板斧：提示词禁止编造、关键参数强制走工具取数、输出端按数值区间硬拦截（文中案例：模温报 180 度实际标准 220 度被拦）。效果数字未披露，只给出工程参数（RAG top_k 4-6 最稳、温度 0.1-0.3）。复制门槛：换车间要重接接口和重建知识库，但四层知识库切分（设备手册/维修工单/工艺标准/老师傅经验各一层）与审计日志规范直接可抄，[原文见尧图网络科技](http://www.lpqz.cn/news/86672)。

**机会点**：接口打磨和知识库切分是这类项目最大的工作量——能把它做成「MES HTTP 工具包+四层知识库切分 SOP」模板的团队可以批量交付，第一步找一家已上 MES 的注塑或机加工厂，先跑通单点诊断 Agent。

缺口：工厂规模（产线数/人数）、上线后的响应时长等效果数据未披露。

### 2. 工业智能体四层架构避坑指南：约束校验与集成难度分级 【整厂·注塑·单Agent】

同站另一篇 11 月 24 日的落地复盘，给出从零搭建的单 Agent 分层骨架。结构：感知-认知-决策-执行四层，感知层必须先做语义化（不给「振动值 0.85mm/s」，给「较 2 小时均值升 40%、超同工况 P95」）；核心循环是意图→检索→工具调用→约束校验→不通过则带违规项重新生成→审计日志。人工介入点：安全责任全留人，执行层只到 MES 审批流和 SCADA 中间变量，PLC 直连被明确禁止（毫秒级扫描周期与秒级 Agent 响应时间尺度不匹配，且安全联锁逻辑经过安全认证而 Agent 决策没有）。集成难度分级：MES/ERP 走 REST 最易、SCADA 走 OPC UA 且写权限必须过安全网关、PLC 直连不做。工具链：Qwen2.5-7B/14B 本地部署（vLLM，单张 A100 或两张 4090），复杂推理上 70B，工具调用用蒸馏 7B 加 AWQ/GPTQ 4bit 量化（延迟降约 40%）；Spring AI 加自研 OPC UA 封装与 Drools 规则引擎。护栏三条硬规矩：数值边界写死在规则引擎（模温 180-260 度、保压 2-8 秒）而不是靠提示词、RAG 引用强制且校验来源存在、无历史先例的调整自动降级为仅供参考不进执行流；数字孪生偏差超 10% 则 Agent 决策不可信。效果数字未披露（有经验数字：数据准备占 70% 工时、自动标注准确率约 70%、约束校验曾拦下超出设备额定值的注塑压力建议），[原文见尧图网络科技](http://www.lpqz.cn/news/154212)。

**机会点**：约束校验循环和参数下发网关每个项目都在自研重写——把它们做成可配置的「工艺边界规则包」（先做注塑模温/保压这类成熟边界）卖给 MES 集成商，第一步把文中规则写成规则引擎配置模板并找一个试点产线验证拦截率。

缺口：作者所服务工厂的具名信息与规模、上线效果数据未披露。

### 3. MFG-Agent 五面架构论文：模型提议、求解器求解、孪生验证、人授权 【整厂·其他·多Agent】

CSDN AI Agent 社区 11 月 24 日刊发的企业级制造运营多智能体系统论文，把「怎么搭」形式化到了可审计级别。结构：数据面、工具面、智能体面、验证面、治理面五面架构，七个关键机制（时间尺度感知的任务分解、角色化提议、类型化工具网关、证书式孪生验证、求解器在环、带血统记忆、分级自治）；计划、排程、工艺、质量、设备、安全、追溯七个角色在各自主权限内提出候选动作，经典求解器做定量分配，数字孪生与约束检查器在提交前做压力测试。人工介入点：治理层按风险分级把动作路由给有权限的人，安全动作只提示与升级、绝不执行，智能体不进安全回路、不改安全仪表系统配置。工具链：与大模型解耦，模型经受控网关调用；工具以最小权限账号对接 ERP、MES、APS、SCADA、历史库、PLM、CMMS；全过程写入只追加的决策账本，决策轨迹可重建。护栏：类型化工具网关统一做参数校验、单位换算、权限检查、幂等执行与补偿，高风险动作须持有验证证书才可提交。效果：无效果数据——论文明确声明未完成现场部署，所有实验单元格为待实测占位，这点写得非常诚实。复制门槛：给出了从只读问答到有界自治的分阶段部署检查清单和评测协议，但行业数据模型需实例化，[原文见 CSDN Agent 社区](https://agent.csdn.net/6b0501abe5f4ca4eff93708f.html)。

**机会点**：论文把「验证证书+决策账本+分级自治」写成了一套可审计的治理骨架——有工业安全背景的团队可据此做分阶段自治评估服务，第一步给已上 MES 的大厂按文中清单做只读问答的影子模式试点，产出可交差的风险评估报告。

缺口：无实测效果数据（论文自声明）、未在任何工厂部署。

## 第二部分：国外

### 1. 西门子 Autonomous Production Planner：多 Agent 排产过完孪生验证才下发 【排产调整·电子代工·多Agent】

西门子 11 月 24 日 SPS 2026 新闻稿发布 Autonomous Production Planner，装在其工业 AI 编排软件 Intelligence Center X 里。场景是电子代工排产，西门子自家 Erlangen 电子工厂同场还展示了 AI 机器人自主拆包来料。结构：多个 AI Agent 协同生成生产排程，并按预定义 KPI 自动优化；每一份排程在释放到生产之前，必须先在物理数字孪生里验证通过。人工介入点：发布权留在验证流程末端，班组级审批细节未披露。工具链：西门子自研编排平台+物理孪生验证；数据底座靠资产管理壳（AAS）标准，已覆盖超过 12 万个硬件产品的标准化机器可读数据。护栏：孪生验证本身就是护栏——仿真不过关的排程出不去；同时把网络安全按欧盟《网络弹性法案》准备。效果数字为厂商预期：人工排产工作量减 70%、成本最多降 20%（非实测）。复制门槛：深度绑定 Intelligence Center X 与西门子自动化栈，换厂要接 AAS 标准数据；Agent 数量与分工、所用模型未披露，[新闻稿见西门子官网](https://press.siemens.com/global/en/pressrelease/siemens-advances-its-automation-portfolio-toward-ai-powered-autonomous-production)。

**机会点**：「排程下发前先过一遍仿真验证」这个环节西门子绑在自家全家桶上，国产 MES 生态没有等价物——轻量仿真团队可以给国产 MES 补这个位，第一步找一家节拍敏感的汽配厂，对插单/急单重排方案做仿真校验试点。

缺口：Agent 具体数量与分工、模型选型、审批节点设计未披露。

### 2. 亚马逊 K-Hub AI 维护助手：数百万维修报告喂出来的诊断 Agent 【设备维护·其他·未披露】

亚马逊 11 月 24 日公布由 AWS 建的维护助手 K-Hub AI，已在全球数百个履约中心上线。原来技术员接到输送线停机，要在手册、历史维修报告、备件库几个互不打通的系统里翻找，欧洲的技术员无从知道纳什维尔同事三天前刚修过一模一样的故障。结构：单一入口的诊断 Agent，把症状链接到可能原因、处理程序链到对应厂商手册、备件链到全网可用库存；特色功能是拍照查备件（Parts Visual Search）和复发性故障自动预警提醒责任人。人工介入点非常明确：判断永远留在技术员，系统从不指令化，公司安全政策优先于任何建议。工具链：AWS 云构建，架构为知识图谱+语义层治理+Agent 路由+混合 AI；底层数据是数百万份维修报告、数十万备件主数据、数千份手册与规程。护栏：每个回答必须指向具体官方文档，授权来源里没有的信息就明说不知道而非编造——这在可能涉及安全的维护环境里是硬要求。效果数字：备件识别从每件 10 分钟降到 5 秒内；无标签备件从 30 分钟翻目录加最长 11 小时等人辨认，降到 2 分钟内；拍照查件自 2026 年 8 月上线以来常规使用率 70%、交互量月增 28%。复制门槛：价值来自全网维修数据沉淀，单厂冷启动难——亚马逊也明说同样的 AWS 构件可供任何有数据积累的组织复用，[原文见 About Amazon](https://www.aboutamazon.eu/news/aws/amazons-new-ai-agent-can-diagnose-a-breakdown-in-seconds-by-drawing-on-millions-of-past-repairs-worldwide)。

**机会点**：跨厂维修知识库的冷启动是明确空位——设备密集的连锁型工厂（食品饮料、锂电光伏）可按机型聚合历史维修工单先喂诊断 Agent，第一步选停机损失最大的一条产线上「拍照查备件」单点功能，两周量级就能看到技术员是否真的天天用。

缺口：底层模型选型、停机时长变化的具体数据、覆盖站点的确切数字未披露（仅「数百站点」）。

### 3. 西门子仿真 Agent 验收四道门：把老师傅经验写成可执行的验收标准 【工艺研发·其他·未披露】

西门子工程师 11 月 24 日的博客，正面回答了工厂工艺研发环节 Agent 落地最尖锐的问题：仿真 Agent 的结果看起来完全合理，错了就是设计决策，怎么敢信。结构：仿真 Copilot 现有三种形态——工具内助手、编排多工具的外部平台、裸 MCP 服务器；Agent 被定位为「初级工程师」而不是替代者，人保留物理、数值方法和对结果的预期。人工介入点：工程师只做两件事——写清任务规格、定义验收门禁，第四道门（实测数据比对）的放行权在人。护栏是一套四层验收门：①数值（残差收敛、网格无关性）；②第一性原理（质量/动量/能量平衡闭合到数值零——进产线的零件必须出线或滞留缓存）；③合理性（量级、对称性、手算校核）；④实测数据（与试验台或现场数据比对）。验收标准全部给了数字：电机热仿真能量平衡闭合须在 1% 内、峰值绕组温度与试验台数据差 5K 内；产线物流仿真至少 10 次重复实验、吞吐置信区间 ±3%、Little 定律偏差 5% 内。效果数字未披露。复制门槛：验收标准库本身就是资产——老师傅每抓一个坑就写成一条门禁，经验随库留人；但这些标准与工艺域知识强绑定，换行业必须重写，[原文见西门子博客](https://blog.siemens.com/2026/11/nobody-photographs-the-copilot-slide-anymore)。

**机会点**：把老师傅脑子里没写下来的经验写成可执行验收清单，是工厂最难外包又最值得外包的活——工艺背景出身的工程师可按行业（电机、汽配先行）打包「验收门禁模板库」做交付，第一步挑一家做仿真的工厂，把人工逐条审报告改成门禁脚本跑。

缺口：落地工厂与运行效果数据未披露。

## 本篇机会点小结

**一、最值得动手的一条**：第 1 条。给已上 MES 的中型工厂做「单点诊断 Agent + MES 审批单回写」的模板化交付。理由：架构、护栏、接口细节全都有公开复盘可抄，工具链全开源（LangGraph+私有化 Qwen+OPC UA 网关），「读自动、写审批」这条红线让甲方安全和工艺团队容易点头。给工业软件集成商或 2-3 人小团队做，第一步照原文复刻 MES HTTP 工具函数与四层知识库切分，1-3 个月就能拿到第一个「故障诊断响应时长缩短」的正反馈。

**二、被验证的需求**：第 5 条亚马逊 K-Hub AI 是本篇唯一带真实使用数据的条目——拍照查备件常规使用率 70%、交互月增 28%、单次识别从 10 分钟降到 5 秒内，说明「维修知识+备件检索」是工人真用、真省时间的功能，不是汇报功能；第 4 条西门子给出人工排产工作量减 70% 的预期值并已产品化发布，说明大厂排产 Agent 已从试点进入正式产品线。

**三、明显的空位**：第 2、3 条把护栏讲得最透（约束校验循环、参数下发网关、验证证书、决策账本），但没有一家把它做成标准件——两条国内条目全是自研代码，每家工厂重写一遍模温边界；第 4 条的排程孪生预验证绑定西门子全家桶，国产 MES 生态没有等价物；第 6 条点出「老师傅经验写成验收门禁」这件事本身没有供应商在做。

**四、本篇结论**：工厂 Agent 已从「答得对不对」进入「敢不敢让它写」的阶段，今天所有条目的共识是 Agent 只提议、确定性代码把关、人签发写操作——剩下的生意不在编排框架（已经卷平了），在把护栏和验收标准做成可复制的标准件。
