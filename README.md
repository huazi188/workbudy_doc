# 定时情报日报归档库

本仓库由 **WorkBuddy 自动化定时任务**自动归档，保存每日各专题的情报汇总与机会点分析。

- 更新方式：GitHub Git Data API 批量提交（每次一个 commit）
- 执行节奏：**隔天执行**（并非每天），每天 06:00–10:00 之间错峰跑完 17 个任务
- 文件编码：UTF-8，Markdown

## 二、每份日报的固定结构

所有日报共用同一套骨架（模板统一维护、批量下发），自上而下固定五段：

| 顺序 | 段落 | 作用 |
|---|---|---|
| 1 | `【语言：全中文】` | 语言约束声明，正文不得出现英文词条 |
| 2 | `【条目汇总表】` | 全文唯一的总表，列：`# / 条目 / 关键事实（含数据） / 机会点摘要 / 标签` |
| 3 | `【机会点汇总表】` | 决策表，列：`# / 机会点 / 类别 / 赛道 / 启动成本 / 验证周期 / 第一步 / 证据来源` |
| 4 | 正文 | 逐条展开，**每条消息后紧跟该条的逐条机会点标注** |
| 5 | `【本篇机会点小结】` | 当日全部机会点的归纳判断（哪些值得做、哪些是伪需求） |

**关于表格的硬规则**：全篇**只放这一张**条目汇总表、**只放这一张**机会点汇总表，均置于全文最前（概览之后、正文之前）。不允许按板块、按地区、按每条消息分别建表。

三张表的分工：

- **条目汇总表** —— 事实层，回答「今天发生了什么」
- **机会点汇总表** —— 决策层，回答「哪些能做、成本多少、第一步怎么走」
- **本篇机会点小结** —— 判断层，回答「我最该抓哪一个、为什么」

## 四、字段口径说明

- **启动成本**：以人民币计，含人力/工具/算力，分「万元以下 / 1–10 万 / 10 万以上」
- **验证周期**：从启动到拿到第一个可判断信号的时间，通常 2 周–3 个月
- **第一步**：能在一周内动手完成的最小动作，不接受「调研一下」这类空话
- **证据来源**：必须可回溯到具体报道、财报、官方公告或产品页面
