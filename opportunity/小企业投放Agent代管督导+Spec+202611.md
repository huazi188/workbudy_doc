## MVP 目标和用户

小型电商店主采购，店主和现有代投操盘手核对报表。 在获授权的样本上完整演示一次从接收输入到交付、复核和取证的流程。

**交付件和输入** 用授权广告账单、平台投放日报及订单退款，出逐日支出、归因差异及调整建议。

**对照流程** 对照平台自报ROAS与店主手工净收入账，观察消耗异常发现时长。

## 功能和验收

| 功能 | 验收方式 |
|---|---|
| P0 · 录入样本和基线 | 记录样本来源、授权、日期与纳入理由，锁定对照范围。必填信息缺失则退回补齐。 |
| P0 · 生成或制作业务交付件 | 按下述试点样本覆盖正常项和例外项，验收人能复核每项结论所依据的输入。 |
| P0 · 复核和业务接收 | 记录复核人、修订项、操作时间与最终状态。触及场景边界时暂停，交还原流程负责人。 |
| P0 · 验收证据 | 交付原流程和试点结果的同口径对照，列出分子、分母、测量区间、缺测和失败项。 |
| P1 · 后续扩展 | 首次流程验收并出现真实购买信号后，评审接入频率、角色范围和数据覆盖。 |

**测量协议** 先回顾既有广告组的近7天报表，建立ROAS归因窗口后用一个有预算上限的小组测试。

**首轮验收门槛** 3家门店各跑7天，实际支出与账单日汇总误差≤2%，超预算自动消费0笔。

## 最小权限与异常处理

工具归因可能重复计入退款单，财务账优先，预算调整与账户变更由店主确认。 样本授权、输入版本与人工修改均应可追溯。由业务验收人确认输出用途，原流程负责人能够停止试点并接回未完成任务。

## 业务验收

按监测广告账户月费，向参加两周试点的3家中至少拿1家实际续费。 状态按样本可用、试点交付、业务验收、付费确认逐项记录。评审结论为 **GO · 验证需求与付费**。已落实数据授权、业务负责人和对照基线后，方可启动受控试点。
