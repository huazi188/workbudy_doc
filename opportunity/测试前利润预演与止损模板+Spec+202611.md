## MVP 目标和用户

备首轮广告预算的独立站新卖家采购，运营或财务输入采购、广告及履约成本。 在获授权的样本上完整演示一次从接收输入到交付、复核和取证的流程。

**交付件和输入** 交付单SKU利润预演表和停投阈值，计算平台费、折扣、物流、退款准备和四种获客成本情景。

**对照流程** 以只看ROAS和进货毛利的旧表为基线，逐笔核对广告账、退款与物流。

## 功能和验收

| 功能 | 验收方式 |
|---|---|
| P0 · 录入样本和基线 | 记录样本来源、授权、日期与纳入理由，锁定对照范围。必填信息缺失则退回补齐。 |
| P0 · 生成或制作业务交付件 | 按下述试点样本覆盖正常项和例外项，验收人能复核每项结论所依据的输入。 |
| P0 · 复核和业务接收 | 记录复核人、修订项、操作时间与最终状态。触及场景边界时暂停，交还原流程负责人。 |
| P0 · 验收证据 | 交付原流程和试点结果的同口径对照，列出分子、分母、测量区间、缺测和失败项。 |
| P1 · 后续扩展 | 首次流程验收并出现真实购买信号后，评审接入频率、角色范围和数据覆盖。 |

**测量协议** 用一家店历史失败品重放30单，验证亏损起点和可承受获客成本再上小额试投。

**首轮验收门槛** 抽核30条已完成订单，净贡献毛利合计误差≤2%，四个情景和止损触发均可复算。

## 最小权限与异常处理

把归因销售当实收或遗漏退货滞后。区分支付、履约和退款观察窗口并核实币种。 样本授权、输入版本与人工修改均应可追溯。由业务验收人确认输出用途，原流程负责人能够停止试点并接回未完成任务。

## 业务验收

模板按免费版获需求线索，按店或SKU核算收费，以两家运行后为审计签单验证。 状态按样本可用、试点交付、业务验收、付费确认逐项记录。评审结论为 **GO · 验证需求与付费**。已落实数据授权、业务负责人和对照基线后，方可启动受控试点。
