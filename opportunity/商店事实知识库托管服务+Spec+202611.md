## MVP 目标和用户

已上线独立站的出海小品牌采购，商品运营与客服共同维护事实。 在获授权的样本上完整演示一次从接收输入到交付、复核和取证的流程。

**交付件和输入** 把发货截止、适用地区、付款和退换货政策做成有负责人、更新时间与审核来源的事实库。

**对照流程** 以网站分散条款和人工回答为基线，对照一致性、更新时延和查证步骤。

## 功能和验收

| 功能 | 验收方式 |
|---|---|
| P0 · 录入样本和基线 | 记录样本来源、授权、日期与纳入理由，锁定对照范围。必填信息缺失则退回补齐。 |
| P0 · 生成或制作业务交付件 | 按下述试点样本覆盖正常项和例外项，验收人能复核每项结论所依据的输入。 |
| P0 · 复核和业务接收 | 记录复核人、修订项、操作时间与最终状态。触及场景边界时暂停，交还原流程负责人。 |
| P0 · 验收证据 | 交付原流程和试点结果的同口径对照，列出分子、分母、测量区间、缺测和失败项。 |
| P1 · 后续扩展 | 首次流程验收并出现真实购买信号后，评审接入频率、角色范围和数据覆盖。 |

**测量协议** 先用一个市场跑两周，模拟错区运费、节前截止变化和无法退款三个边界案例。

**首轮验收门槛** 5店上线第一批经签核事实，每店从至少30条高频问答抽检，正确出处可追溯率≥98%，政策变更1工作日内入库。

## 最小权限与异常处理

过期本地条款传播到多个购物入口。逐市场版本管理并回收过期条目，差异进入人工队列。 样本授权、输入版本与人工修改均应可追溯。由业务验收人确认输出用途，原流程负责人能够停止试点并接回未完成任务。

## 业务验收

按站收初始化费并按月做差异巡检，以第二个地区或节前更新的订单验证续约。 状态按样本可用、试点交付、业务验收、付费确认逐项记录。评审结论为 **GO · 验证需求与付费**。已落实数据授权、业务负责人和对照基线后，方可启动受控试点。
