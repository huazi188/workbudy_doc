## MVP 目标和用户

自建售后 Agent 的电商客服负责人采购，客服质检和研发共同验收。 在获授权的样本上完整演示一次从接收输入到交付、复核和取证的流程。

**交付件和输入** 用店铺 FAQ、合成订单响应和转人工规则交付三层架构检查表、可重放对话及整改清单。

**对照流程** 对照现有全提示词 Agent 或现行工作流，比较每100单解决正确率和人工交接次数。

## 功能和验收

| 功能 | 验收方式 |
|---|---|
| P0 · 录入样本和基线 | 记录样本来源、授权、日期与纳入理由，锁定对照范围。必填信息缺失则退回补齐。 |
| P0 · 生成或制作业务交付件 | 按下述试点样本覆盖正常项和例外项，验收人能复核每项结论所依据的输入。 |
| P0 · 复核和业务接收 | 记录复核人、修订项、操作时间与最终状态。触及场景边界时暂停，交还原流程负责人。 |
| P0 · 验收证据 | 交付原流程和试点结果的同口径对照，列出分子、分母、测量区间、缺测和失败项。 |
| P1 · 后续扩展 | 首次流程验收并出现真实购买信号后，评审接入频率、角色范围和数据覆盖。 |

**测量协议** 首期限制到查件和政策 FAQ，两条流程各取既有成功和边界案例，观察不同版本的误路由。

**首轮验收门槛** 80 条盲测中工具状态匹配率≥95%，错误写操作0次，失败交接可追溯率100%。

## 最小权限与异常处理

订单越权或服务超时会带来错答，订单查询受身份校验约束，超时进入人工队列。 样本授权、输入版本与人工修改均应可追溯。由业务验收人确认输出用途，原流程负责人能够停止试点并接回未完成任务。

## 业务验收

按一个售后场景收体检费，拿同一份整改清单报价验证团队是否愿为复验追加预算。 状态按样本可用、试点交付、业务验收、付费确认逐项记录。评审结论为 **GO · 验证需求与付费**。已落实数据授权、业务负责人和对照基线后，方可启动受控试点。
