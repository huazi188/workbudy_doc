## MVP 目标和用户

邮件客服主管采购，质检、班组长和审核客服使用。 在获授权的样本上完整演示一次从接收输入到交付、复核和取证的流程。

**交付件和输入** 用草稿版本、人工发出文本和工单结果形成按意图的改写原因、未编辑率及放量建议。

**对照流程** 对照主管凭经验选放量范围，比较逐条人工确认的改写工时及再次来信率。

## 功能和验收

| 功能 | 验收方式 |
|---|---|
| P0 · 录入样本和基线 | 记录样本来源、授权、日期与纳入理由，锁定对照范围。必填信息缺失则退回补齐。 |
| P0 · 生成或制作业务交付件 | 按下述试点样本覆盖正常项和例外项，验收人能复核每项结论所依据的输入。 |
| P0 · 复核和业务接收 | 记录复核人、修订项、操作时间与最终状态。触及场景边界时暂停，交还原流程负责人。 |
| P0 · 验收证据 | 交付原流程和试点结果的同口径对照，列出分子、分母、测量区间、缺测和失败项。 |
| P1 · 后续扩展 | 首次流程验收并出现真实购买信号后，评审接入频率、角色范围和数据覆盖。 |

**测量协议** 先观察订单状态邮件，不对外代发，以同群组的人工处理记录判断是否扩大试点。

**首轮验收门槛** 100封同意图影子邮件中实质无改写占比≥90%，政策或隐私错误0条，再联系率不升。

## 最小权限与异常处理

仅按字面差异会漏掉错答与过度信任，将格式改写和事实改写分别复核。 样本授权、输入版本与人工修改均应可追溯。由业务验收人确认输出用途，原流程负责人能够停止试点并接回未完成任务。

## 业务验收

按队列月费报价，以一个新增队列和一次收费复验验证付费动机。 状态按样本可用、试点交付、业务验收、付费确认逐项记录。评审结论为 **GO · 验证需求与付费**。已落实数据授权、业务负责人和对照基线后，方可启动受控试点。
