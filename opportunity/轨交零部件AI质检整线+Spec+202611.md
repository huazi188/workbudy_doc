## 1. 核心规格

### 1.1 产品定义

**产品名称**：轨交零部件AI视觉质检整线（标准复制包）

**一句话定义**：把"46秒节拍+95%字符识别+90%缺陷识别"的轨交质检整线，以标准化方式复制到同类零部件厂，并提供可签字的验收指标而非只卖系统。

**核心差异化**：
- 其他方案商：卖设备/卖算法，客户自己定义验收标准
- 本产品：**先出验收标准，再出系统**，降低客户决策风险

### 1.2 目标用户画像

**主要用户（生产质量决策层）**：
- 职位：质量总监、生产副总、技术总监
- 公司规模：员工200-2000人，年收入1-10亿元的轨交零部件制造商
- 产品类型：垫板、扣件、道岔零件、桥梁支座等"品种≤10、批量大、公差严"的产品
- 核心诉求：降低漏检率、满足铁路客户的追溯要求、减少质检人力投入

**次要用户（操作执行层）**：
- 职位：质检班长、设备工程师
- 核心诉求：操作简单、换型快（≤30分钟）、报警清晰、不需要AI专业知识

### 1.3 核心功能

| 功能模块 | 功能描述 | 优先级 |
|---------|---------|--------|
| **视觉检测引擎** | 对零部件进行字符识别（型号/批次）和缺陷识别（裂纹/气孔/尺寸超差） | P0 |
| **节拍控制系统** | 保证单件检测节拍≤50秒（目标46秒），支持连续24小时运行 | P0 |
| **质检记录系统** | 自动归档每件产品的原图、尺寸数据、缺陷判定结果 | P0 |
| **验收报告生成** | 一键生成可提交给铁路局/客户的质量合规报告 | P0 |
| **多品种快换** | 同类零部件换型操作≤30分钟，参数自动加载 | P1 |
| **实时预警看板** | 大屏显示当班不良率、已检数量、当前节拍趋势 | P1 |
| **追溯查询接口** | 按批次、日期、缺陷类型检索历史质检记录 | P1 |
| **MES/ERP对接** | 标准API，与客户现有系统双向同步质检数据 | P2 |
| **参数迁移工具** | 从已有模型快速迁移到新品种，减少重新训练时间 | P2 |

## 2. 功能规格

### 2.1 MVP功能清单（P0：必须有）

#### 功能1：视觉检测引擎

**输入**：零部件实物（通过传送带或机械臂送至检测工位）  
**处理**：
- 相机采集：≥2个工业相机，覆盖零件顶面+侧面
- 光源方案：环形光+条形光组合，适应金属表面反光
- 检测算法：字符识别（OCR+CNN组合），缺陷检测（YOLOv8或同级）

**输出**：每件产品的判定结果（合格/不合格/复检），附原图和标注图

**验收标准**：
- 字符识别准确率：≥95%（连续1000件测试）
- 缺陷识别准确率：≥90%（包含裂纹、气孔、变形、尺寸超差四类）
- 漏检率：≤0.5%
- 误检率（好品判为坏）：≤3%

#### 功能2：节拍控制系统

**节拍目标**：46秒/件（±10%，即42-50秒）  
**稳定性要求**：连续8小时运行，节拍波动≤5%  
**故障恢复**：设备异常停线后，≤10分钟内恢复生产  

#### 功能3：质检记录系统

**数据结构**（每条记录包含）：
- 产品ID（扫码或OCR自动获取）
- 检测时间戳
- 相机原图（≥2张）
- 检测结论（合格/不合格/复检）
- 缺陷类型和位置（如有）
- 操作员确认记录（人工复检结果）

**存储**：本地边缘服务器（不要求联网），保存≥3年

#### 功能4：验收报告生成

**报告格式**：PDF，可导出Excel  
**报告内容**：
- 批次总览（总检数、合格率、不良率、主要缺陷类型）
- 不合格品明细（每件产品图片+判定原因）
- 质检员签名栏（电子签章或手写签名区）
- 符合标准说明栏（可填写对应的铁路行业标准编号）

### 2.2 P1功能详细说明

#### 多品种快换

**触发场景**：生产计划换型，从垫板A切换到垫板B  
**操作流程**：
1. 操作员在触摸屏上选择新品种
2. 系统自动加载对应的检测参数（相机位置/光源参数/判定阈值）
3. 操作员放入3件样品做自动校验
4. 校验通过后（≤5分钟），正式切换生产

**时间要求**：从选择品种到通过校验，≤30分钟

#### 实时预警看板

**显示内容**：
- 当班总产量 / 合格数 / 不合格数
- 实时不良率折线图（以小时为粒度）
- 当前节拍仪表（绿黄红三色预警）
- 最近5件不合格品缩略图

**预警触发**：
- 不良率超过设定阈值（默认5%），声光报警
- 节拍连续3件超过60秒，提示维护

## 3. 成功指标

### 3.1 业务指标

| 指标 | Phase 1目标（8周末） | Phase 2目标（6个月末） | Phase 3目标（12个月末） |
|------|---------------------|----------------------|----------------------|
| POC客户数 | 1个 | 3个 | 5个 |
| 整线部署客户数 | 0 | 1 | 3 |
| 年维护合同数 | 0 | 1 | 3 |
| 累计收入 | 15-25万 | 100-200万 | 400-700万 |
| 客户ROI（回收周期） | - | ≤24个月 | ≤18个月 |

### 3.2 产品指标

| 指标 | 目标值 | 测量方式 |
|------|--------|---------|
| 节拍达标率 | ≥90%（46±10秒内的件数占比） | 系统自动记录 |
| 字符识别准确率 | ≥95% | 每月抽样复核100件 |
| 缺陷识别准确率 | ≥90% | 质检员对不合格品的复核结论 |
| 系统可用率 | ≥98%（7×24小时） | 停线记录 |
| 换型时间 | ≤30分钟 | 操作日志时间戳 |

### 3.3 验证方法

**POC验证（4-6周）**：
- 在客户工厂单工位安装，连续运行5个工作日
- 客户质量部抽取500件实物与系统结论对比
- 形成三方认可的验收报告（供应商/客户/检验机构）

**整线验证（持续监测）**：
- 每月生成质量月报
- 季度客户满意度访谈

## 5. 技术架构

### 5.1 系统组件

```
硬件层:
├── 工业相机（≥2台，500万像素以上）
├── LED光源（环形+条形，可编程亮度）
├── 传送带/定位机构（适配客户产线节拍）
├── 边缘计算服务器（GPU，不联外网）
└── 触摸屏操作台（15吋以上）

软件层:
├── 视觉检测引擎（字符识别+缺陷检测模型）
├── 节拍调度模块（与传送带/机械臂联动）
├── 数据存储模块（本地SQLite/PostgreSQL）
├── 报告生成模块（PDF/Excel导出）
└── 操作界面（Web应用，Chrome浏览器访问）

可选扩展:
└── MES/ERP对接接口（REST API）
```

### 5.2 技术栈

| 层级 | 技术选型 | 理由 |
|------|---------|------|
| 检测模型 | YOLOv8 + PaddleOCR | 轻量化，可在边缘GPU上实时推理 |
| 后端 | Python FastAPI | 快速开发，AI生态成熟 |
| 前端 | React + Ant Design | 工业界面成熟组件 |
| 数据库 | PostgreSQL（本地） | 稳定，支持大量图片元数据 |
| 图片存储 | MinIO（本地对象存储） | 私有化，不依赖云 |
| 部署 | Docker + 边缘服务器 | 交付标准化，客户IT无需配合 |

### 5.3 成本预算（单个整线项目）

| 成本项 | 金额 | 说明 |
|--------|------|------|
| 硬件（相机+光源+服务器） | 15-25万元 | 进口相机+国产光源 |
| 传送带/机构（适配） | 10-20万元 | 因客户产线差异较大 |
| 软件开发（首个项目摊销） | 10万元 | 后续项目降低 |
| 实施调试（工程师3个月） | 15-20万元 | 2名工程师驻场 |
| **项目总成本** | **50-75万元** | 对应报价80-150万，毛利40-50% |

## 6. Go/No-Go 标准

### 6.1 进入整线开发的条件（Phase 1结束时）

- ✅ 至少1个POC通过客户验收（节拍≤50秒，识别率≥90%）
- ✅ 访谈中60%+受访者给出整线支付意愿（≥80万元）
- ✅ 有1名制造业背景合伙人/顾问到位
- ✅ 种子资金（200-400万元）到位或确认来源

### 6.2 继续到Phase 3的条件（整线第一个完成时）

- ✅ 整线连续运行30天，系统可用率≥98%
- ✅ 客户方质检员减少≥2名（量化ROI）
- ✅ 客户签署年维护合同
- ✅ 有≥3家工厂表达整线意向

### 6.3 停止条件

- ❌ 2个POC均未通过客户验收（技术路径有根本问题）
- ❌ 访谈中支付意愿普遍低于30万元（商业模式不成立）
- ❌ 大厂（海康/旷视）以同类标准包、低于我们30%的价格进入同一赛道
