## MVP 目标和用户

拥有本地工作站的独立开发者、小设计团队买单，技术同事负责装机。 在获授权的样本上完整演示一次从接收输入到交付、复核和取证的流程。

**交付件和输入** 提供基于已验证实际硬件的依赖检查、模型权重授权核验、可复跑安装和容量对照说明。

**对照流程** 与照搬通用教程相比，测首个可用请求耗时、依赖冲突和重复安装成功率。

## 功能和验收

| 功能 | 验收方式 |
|---|---|
| P0 · 录入样本和基线 | 记录样本来源、授权、日期与纳入理由，锁定对照范围。必填信息缺失则退回补齐。 |
| P0 · 生成或制作业务交付件 | 按下述试点样本覆盖正常项和例外项，验收人能复核每项结论所依据的输入。 |
| P0 · 复核和业务接收 | 记录复核人、修订项、操作时间与最终状态。触及场景边界时暂停，交还原流程负责人。 |
| P0 · 验收证据 | 交付原流程和试点结果的同口径对照，列出分子、分母、测量区间、缺测和失败项。 |
| P1 · 后续扩展 | 首次流程验收并出现真实购买信号后，评审接入频率、角色范围和数据覆盖。 |

**测量协议** 先选两个已持有的工作站型号，用同一组授权本地小模型和公开测试请求跑复现，发布实体验证范围。

**首轮验收门槛** 拟5种可取得的干净环境，4种能在60分钟内完成首个测试，全部输出日志与卸载说明。

## 最小权限与异常处理

硬件或模型未确认兼容时容易超出显存，提前做内存能力诊断并将兼容表绑定版本。 样本授权、输入版本与人工修改均应可追溯。由业务验收人确认输出用途，原流程负责人能够停止试点并接回未完成任务。

## 业务验收

一次性教程脚本加可选远程辅导，收集首批5个实付订单和退款原因。 状态按样本可用、试点交付、业务验收、付费确认逐项记录。评审结论为 **GO · 验证需求与付费**。已落实数据授权、业务负责人和对照基线后，方可启动受控试点。
