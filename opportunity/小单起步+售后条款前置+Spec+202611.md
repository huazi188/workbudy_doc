## MVP 目标和用户

已找个人开发者做过官网或小程序的小微老板采购，店员提工单。 在获授权的样本上完整演示一次从接收输入到交付、复核和取证的流程。

**交付件和输入** 交付一页可售样品、分级售后服务目录、变更受理及备份恢复流程，按客户授权域名、仓库及系统版本记档。

**对照流程** 以一次性交付后的临时返工为对照，比较故障响应、周期内修改请求量和每客户维护工时。

## 功能和验收

| 功能 | 验收方式 |
|---|---|
| P0 · 录入样本和基线 | 记录样本来源、授权、日期与纳入理由，锁定对照范围。必填信息缺失则退回补齐。 |
| P0 · 生成或制作业务交付件 | 按下述试点样本覆盖正常项和例外项，验收人能复核每项结论所依据的输入。 |
| P0 · 复核和业务接收 | 记录复核人、修订项、操作时间与最终状态。触及场景边界时暂停，交还原流程负责人。 |
| P0 · 验收证据 | 交付原流程和试点结果的同口径对照，列出分子、分母、测量区间、缺测和失败项。 |
| P1 · 后续扩展 | 首次流程验收并出现真实购买信号后，评审接入频率、角色范围和数据覆盖。 |

**测量协议** 先做一套能离线演示的网页样品，挑可演示回滚的网站修改，与既有客户获取付款及取消理由。

**首轮验收门槛** 拟两周向10家符合客群的客户报价，至少2笔实付维护单，并在约定时限内完成一次改字和一次备份恢复演练。

## 最小权限与异常处理

无限次修改压缩利润，合同定义改字额度、响应窗口和重大变更另报，由客户持有域名与账号。 样本授权、输入版本与人工修改均应可追溯。由业务验收人确认输出用途，原流程负责人能够停止试点并接回未完成任务。

## 业务验收

每站点每年含小额改动，超额按工时定价，对同一批客户并行验证一次性与含维护两种报价。 状态按样本可用、试点交付、业务验收、付费确认逐项记录。评审结论为 **GO · 验证需求与付费**。已落实数据授权、业务负责人和对照基线后，方可启动受控试点。
