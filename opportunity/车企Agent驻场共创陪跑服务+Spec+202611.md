## MVP 目标和用户

区域车企或供应商的数字化转型部门立项，制造或质量骨干与驻场顾问使用。 在获授权的样本上完整演示一次从接收输入到交付、复核和取证的流程。

**交付件和输入** 依据操作记录与现有权限，交付一个非控制类服务助手、流程地图、验收回放和驻场交接材料。

**对照流程** 对照企业内部IT需求排队及传统驻场，比较反馈周期和业务人员复用率。

## 功能和验收

| 功能 | 验收方式 |
|---|---|
| P0 · 录入样本和基线 | 记录样本来源、授权、日期与纳入理由，锁定对照范围。必填信息缺失则退回补齐。 |
| P0 · 生成或制作业务交付件 | 按下述试点样本覆盖正常项和例外项，验收人能复核每项结论所依据的输入。 |
| P0 · 复核和业务接收 | 记录复核人、修订项、操作时间与最终状态。触及场景边界时暂停，交还原流程负责人。 |
| P0 · 验收证据 | 交付原流程和试点结果的同口径对照，列出分子、分母、测量区间、缺测和失败项。 |
| P1 · 后续扩展 | 首次流程验收并出现真实购买信号后，评审接入频率、角色范围和数据覆盖。 |

**测量协议** 选售后配件查询或质量记录检索，约定一位业务负责人与一位IT负责人员每周评审。

**首轮验收门槛** 两周内完成一个跨角色签认的小场景，30个回放任务达到≥90%合格，交接演练由客户完成1次。

## 最小权限与异常处理

驻场范围扩张与研发文档泄密，以固定场景范围和最小访问权限验收，按约定清理副本。 样本授权、输入版本与人工修改均应可追溯。由业务验收人确认输出用途，原流程负责人能够停止试点并接回未完成任务。

## 业务验收

按上线场景及驻场人日报价，通过时段明确的付费共创合同测试。 状态按样本可用、试点交付、业务验收、付费确认逐项记录。评审结论为 **GO · 先验证需求，再决定试点**。已落实数据授权、业务负责人和对照基线后，方可启动受控试点。
