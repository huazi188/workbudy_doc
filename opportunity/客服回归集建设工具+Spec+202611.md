## MVP 目标和用户

客服 SaaS 产品经理或电商质检负责人采购，质检标注人与版本发布人使用。 在获授权的样本上完整演示一次从接收输入到交付、复核和取证的流程。

**交付件和输入** 由脱敏历史工单、售后规则和人工处理记录产出版本化回归集、字段说明及争议记录。

**对照流程** 对照每次发布临时抽查，比较样本覆盖、标注复用率和回归发现问题的时间。

## 功能和验收

| 功能 | 验收方式 |
|---|---|
| P0 · 录入样本和基线 | 记录样本来源、授权、日期与纳入理由，锁定对照范围。必填信息缺失则退回补齐。 |
| P0 · 生成或制作业务交付件 | 按下述试点样本覆盖正常项和例外项，验收人能复核每项结论所依据的输入。 |
| P0 · 复核和业务接收 | 记录复核人、修订项、操作时间与最终状态。触及场景边界时暂停，交还原流程负责人。 |
| P0 · 验收证据 | 交付原流程和试点结果的同口径对照，列出分子、分母、测量区间、缺测和失败项。 |
| P1 · 后续扩展 | 首次流程验收并出现真实购买信号后，评审接入频率、角色范围和数据覆盖。 |

**测量协议** 从一家客户抽近30天工单，双人标注同一对照子集并跑一轮版本回归。

**首轮验收门槛** 80个样本覆盖至少8个业务意图，每类至少5例，复抽20条两人标签一致≥90%。

## 最小权限与异常处理

普通咨询过多会掩盖关键事故，退款、拒收等意图分层抽样，留出冻结测试集。 样本授权、输入版本与人工修改均应可追溯。由业务验收人确认输出用途，原流程负责人能够停止试点并接回未完成任务。

## 业务验收

按工单类目及季度补样计费，向一个 SaaS 团队销售首个单类目包。 状态按样本可用、试点交付、业务验收、付费确认逐项记录。评审结论为 **GO · 验证需求与付费**。已落实数据授权、业务负责人和对照基线后，方可启动受控试点。
