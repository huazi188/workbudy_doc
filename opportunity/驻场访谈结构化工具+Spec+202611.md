## MVP 目标和用户

驻场AI交付团队负责人采购，访谈主持人及需求负责人共同复核。 在获授权的样本上完整演示一次从接收输入到交付、复核和取证的流程。

**交付件和输入** 输入经同意的访谈文本和术语表，交付按证据出处链接的流程图、待验证需求、冲突和责任人清单。

**对照流程** 对照访谈员已有手工纪要与表格，以同一场访谈对比出稿分钟数、关键需求漏记率与争议发现。

## 功能和验收

| 功能 | 验收方式 |
|---|---|
| P0 · 录入样本和基线 | 记录样本来源、授权、日期与纳入理由，锁定对照范围。必填信息缺失则退回补齐。 |
| P0 · 生成或制作业务交付件 | 按下述试点样本覆盖正常项和例外项，验收人能复核每项结论所依据的输入。 |
| P0 · 复核和业务接收 | 记录复核人、修订项、操作时间与最终状态。触及场景边界时暂停，交还原流程负责人。 |
| P0 · 验收证据 | 交付原流程和试点结果的同口径对照，列出分子、分母、测量区间、缺测和失败项。 |
| P1 · 后续扩展 | 首次流程验收并出现真实购买信号后，评审接入频率、角色范围和数据覆盖。 |

**测量协议** 找2至3个团队各选重复性部门访谈，混排人工与工具辅助输出，交需求负责人盲评后对比。

**首轮验收门槛** 拟两周至少12场访谈，初稿准备中位工时下降≥35%，负责人确认的关键需求覆盖≥90%，未经确认的推断全部标记。

## 最小权限与异常处理

录音授权与转写错归因，保留授权范围和来源片段，敏感访谈由客户保存，成果经主持人签审。 样本授权、输入版本与人工修改均应可追溯。由业务验收人确认输出用途，原流程负责人能够停止试点并接回未完成任务。

## 业务验收

按团队月费或每项目场次档位报价，试点后至少1个团队签实付的第二项目包。 状态按样本可用、试点交付、业务验收、付费确认逐项记录。评审结论为 **GO · 验证需求与付费**。已落实数据授权、业务负责人和对照基线后，方可启动受控试点。
