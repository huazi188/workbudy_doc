## MVP 目标和用户

多店连锁市场部门采购，门店经理、客服和CRM管理员共同审批。 在获授权的样本上完整演示一次从接收输入到交付、复核和取证的流程。

**交付件和输入** 接入正式授权CRM和门店目录，生成评论回复及营业信息更新草稿，保留店级审批和回退。

**对照流程** 与各门店手工复制回复和逐网站更新对照处理时间、正确来源及发布责任。

## 功能和验收

| 功能 | 验收方式 |
|---|---|
| P0 · 录入样本和基线 | 记录样本来源、授权、日期与纳入理由，锁定对照范围。必填信息缺失则退回补齐。 |
| P0 · 生成或制作业务交付件 | 按下述试点样本覆盖正常项和例外项，验收人能复核每项结论所依据的输入。 |
| P0 · 复核和业务接收 | 记录复核人、修订项、操作时间与最终状态。触及场景边界时暂停，交还原流程负责人。 |
| P0 · 验收证据 | 交付原流程和试点结果的同口径对照，列出分子、分母、测量区间、缺测和失败项。 |
| P1 · 后续扩展 | 首次流程验收并出现真实购买信号后，评审接入频率、角色范围和数据覆盖。 |

**测量协议** 给同城3店各配置2名审批人，回放临时歇业、投诉评论和错店回复三种边界。

**首轮验收门槛** 3家门店各≥20条样本，跨店数据串用或未审发布0条，审校后的处理时间减少≥30%。

## 最小权限与异常处理

各平台记录写权限不同，错误营业信息影响到访。统一只读验证，发布前校对本店资料。 样本授权、输入版本与人工修改均应可追溯。由业务验收人确认输出用途，原流程负责人能够停止试点并接回未完成任务。

## 业务验收

按接入系统收一次性费用，按门店/月维护，用第二批门店上线采购测试扩展意愿。 状态按样本可用、试点交付、业务验收、付费确认逐项记录。评审结论为 **GO · 先验证需求，再决定试点**。已落实数据授权、业务负责人和对照基线后，方可启动受控试点。
