## MVP 目标和用户

企业安全架构师和智能体产品负责人。 在获授权的样本上完整演示一次从接收输入到交付、复核和取证的流程。

**交付件和输入** 在获授权的单一内部流程上，盘点工具权限、人工确认与日志覆盖。

**对照流程** 与手工权限表和上线评审卡做对照。

## 功能和验收

| 功能 | 验收方式 |
|---|---|
| P0 · 录入样本和基线 | 记录样本来源、授权、日期与纳入理由，锁定对照范围。必填信息缺失则退回补齐。 |
| P0 · 生成或制作业务交付件 | 按下述试点样本覆盖正常项和例外项，验收人能复核每项结论所依据的输入。 |
| P0 · 复核和业务接收 | 记录复核人、修订项、操作时间与最终状态。触及场景边界时暂停，交还原流程负责人。 |
| P0 · 验收证据 | 交付原流程和试点结果的同口径对照，列出分子、分母、测量区间、缺测和失败项。 |
| P1 · 后续扩展 | 首次流程验收并出现真实购买信号后，评审接入频率、角色范围和数据覆盖。 |

**测量协议** 先审阅一个只读知识助手的角色、工具白名单和日志证据。

**首轮验收门槛** ≥20项权限与审计用例，关键越权配置发现项100%复核。

## 最小权限与异常处理

测试影响业务，隔离环境且限定合成账号与禁止生产写入。 样本授权、输入版本与人工修改均应可追溯。由业务验收人确认输出用途，原流程负责人能够停止试点并接回未完成任务。

## 业务验收

按应用及权限路径数量收固定范围风险审查费。 状态按样本可用、试点交付、业务验收、付费确认逐项记录。评审结论为 **GO · 先验证需求，再决定试点**。已落实数据授权、业务负责人和对照基线后，方可启动受控试点。
