## MVP 目标和用户

有内网代码审核要求的研发负责人采购，应用安全与 Java/Kotlin 审核人员使用。 在获授权的样本上完整演示一次从接收输入到交付、复核和取证的流程。

**交付件和输入** 基于客户安全编码准则、SAST报告和合成审核样例交付只读审查规则与修复建议格式。

**对照流程** 对照人工安全检查清单及现有扫描器，比同一批 PR 的误报处理工时。

## 功能和验收

| 功能 | 验收方式 |
|---|---|
| P0 · 录入样本和基线 | 记录样本来源、授权、日期与纳入理由，锁定对照范围。必填信息缺失则退回补齐。 |
| P0 · 生成或制作业务交付件 | 按下述试点样本覆盖正常项和例外项，验收人能复核每项结论所依据的输入。 |
| P0 · 复核和业务接收 | 记录复核人、修订项、操作时间与最终状态。触及场景边界时暂停，交还原流程负责人。 |
| P0 · 验收证据 | 交付原流程和试点结果的同口径对照，列出分子、分母、测量区间、缺测和失败项。 |
| P1 · 后续扩展 | 首次流程验收并出现真实购买信号后，评审接入频率、角色范围和数据覆盖。 |

**测量协议** 选一个自有 Java 服务的测试分支，用安全编码反例和干净样例双盲比较基线。

**首轮验收门槛** 40条预标记变更中既定规则识别率≥90%，误报率≤10%，源代码离开指定环境事件0次。

## 最小权限与异常处理

安全告警混杂风格建议，告警挂接企业规则编号，复审处置由代码所有者决定。 样本授权、输入版本与人工修改均应可追溯。由业务验收人确认输出用途，原流程负责人能够停止试点并接回未完成任务。

## 业务验收

按仓库或研发团队收部署与年度维护费，以一次付费内网评审验证预算。 状态按样本可用、试点交付、业务验收、付费确认逐项记录。评审结论为 **GO · 验证需求与付费**。已落实数据授权、业务负责人和对照基线后，方可启动受控试点。
