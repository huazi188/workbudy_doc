## MVP 目标和用户

经营独立订阅应用的开发者采购，店主和安卓值班人员接收付款事件摘要。 在获授权的样本上完整演示一次从接收输入到交付、复核和取证的流程。

**交付件和输入** 通过服务商官方测试事件生成经开关控制的收款、退款通知，交付到账状态说明与设备权限页。

**对照流程** 与后台网页、日结邮件核对到账通知时延、重复率和退款可辨认度。

## 功能和验收

| 功能 | 验收方式 |
|---|---|
| P0 · 录入样本和基线 | 记录样本来源、授权、日期与纳入理由，锁定对照范围。必填信息缺失则退回补齐。 |
| P0 · 生成或制作业务交付件 | 按下述试点样本覆盖正常项和例外项，验收人能复核每项结论所依据的输入。 |
| P0 · 复核和业务接收 | 记录复核人、修订项、操作时间与最终状态。触及场景边界时暂停，交还原流程负责人。 |
| P0 · 验收证据 | 交付原流程和试点结果的同口径对照，列出分子、分母、测量区间、缺测和失败项。 |
| P1 · 后续扩展 | 首次流程验收并出现真实购买信号后，评审接入频率、角色范围和数据覆盖。 |

**测量协议** 用一套沙盒订阅和一台安卓设备演示首次付款、重复事件、退款与下线开关。

**首轮验收门槛** 用至少30个测试事件，推送正确率≥98%，重复通知0条，P95通知延迟≤60秒。

## 最小权限与异常处理

泄露买家身份或将授权误写到账。通知仅保必要店铺金额与状态，使用最小权限及本地设备认证。 样本授权、输入版本与人工修改均应可追溯。由业务验收人确认输出用途，原流程负责人能够停止试点并接回未完成任务。

## 业务验收

按商户或设备数收小额订阅，收首月实际支付并对比消息量产生的运行成本。 状态按样本可用、试点交付、业务验收、付费确认逐项记录。评审结论为 **GO · 验证需求与付费**。已落实数据授权、业务负责人和对照基线后，方可启动受控试点。
