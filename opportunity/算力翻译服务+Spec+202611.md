## 1. 核心规格

### 1.1 产品定义

**核心价值主张**：帮第一次买Token的创作者和中小商家找到"最适合自己的模型和套餐"，省钱、不踩坑。

**一句话描述**：Token选购的"导购顾问"——把几十种模型套餐翻译成"你该买哪个"。

**解决的核心问题**：
- 问题1：不知道哪个模型性价比最高
- 问题2：不知道哪个适合自己的场景（写作/客服/编程/图片生成）
- 问题3：不知道买多少Token够用
- 问题4：不知道续费时要不要换模型

### 1.2 用户画像

**人群A：内容创作者** (40%)
- 特征：公众号/小红书/即刻作者，月收入5000-2万
- 用途：用AI辅助写作、配图、优化文案
- 痛点：预算有限，希望找到"够用又不浪费"的套餐
- 付费意愿：中等（愿意为"省钱"付费）

**人群B：中小电商商家** (35%)
- 特征：淘宝/京东/拼多多店主，月GMV 10-50万
- 用途：生成商品描述、客服应答、营销文案
- 痛点：Token消耗快，不知道哪个模型最划算
- 付费意愿：高（成本敏感，愿意为"降本"付费）

**人群C：个人开发者** (25%)
- 特征：接私活做AI应用，月收入1-3万
- 用途：API调用、代码生成、数据处理
- 痛点：需要根据项目预算选择合适的模型
- 付费意愿：中等（项目预算内可接受）

### 1.3 核心功能

**P0功能（MVP，Week 1-2上线）**：

1. **对比选购指南**（内容形态）
   - 8大主流模型性能对比表：
     - GPT-4 Turbo / Claude 3.5 Sonnet / 文心一言4.0 / 千问Max / DeepSeek V2 / Kimi / MiniMax / 智谱GLM-4
   - 对比维度：响应速度（ms）、准确率（%）、价格（元/1M tokens）
   - 按场景适配矩阵：
     - 写作场景：推荐模型A、B、C（排序依据：创意能力+价格）
     - 客服场景：推荐模型D、E、F（排序依据：响应速度+稳定性）
     - 编程场景：推荐模型G、H（排序依据：代码能力+上下文长度）
     - 图片生成：推荐模型I、J（排序依据：视觉质量+生成速度）
   - Token用量估算器：
     - 输入：场景类型 + 每日使用频率
     - 输出：推荐套餐 + 预期月消耗 + 月成本预估
   - 发布渠道：知乎长文（3000字）+ 小红书图文（9图）+ 即刻帖子（800字）

2. **1对1选型咨询**（人工服务）
   - 收集信息问卷（5分钟）：
     - 您主要用AI做什么？（写作/客服/编程/图片生成/其他）
     - 您每天大概用几次？（1-10次 / 10-50次 / 50次以上）
     - 您的月预算是多少？（100元以下 / 100-500元 / 500-1000元 / 1000元以上）
     - 您最看重什么？（价格 / 速度 / 准确率 / 功能全面）
     - 您之前用过哪些模型？满意吗？
   - 输出：选型报告PDF（3页）
     - 第1页：您的使用场景分析
     - 第2页：推荐模型Top 3（含对比表）
     - 第3页：购买建议（套餐+月成本+省钱Tips）
   - 定价：200元/次
   - 交付时间：24小时内

## 5. 技术架构

### 5.1 系统组件

**前端系统**：
- 内容展示：知乎/小红书/即刻（静态内容）
- 在线问卷：Typeform / 腾讯问卷（Phase 1）
- Token估算器：简单HTML+JS工具（嵌入文章）
- 自动化问卷系统：Web App（Phase 2）

**后端系统**：
- 对比数据库：Excel / Notion（Phase 1人工维护）
- 决策树引擎：Python脚本（Phase 2自动生成报告）
- 用量监测服务：Python + API对接（Phase 2）
- 报告生成：Python + PDF库（自动化）

**数据存储**：
- 用户数据：Notion / Airtable（Phase 1）
- 咨询记录：微信+Excel（Phase 1）
- 监测数据：PostgreSQL（Phase 2）

**第三方集成**：
- 支付：微信支付 / 支付宝
- 客服：微信 / 企业微信
- 数据源：各模型官网API（价格/性能数据）

### 5.2 技术栈

**Phase 1（人工服务为主）**：
- 内容制作：Figma（图表）+ Markdown（文章）
- 问卷工具：Typeform / 腾讯问卷
- 数据管理：Excel + Notion
- 报告生成：Word + PDF导出

**Phase 2（自动化）**：
- 前端：React + Next.js
- 后端：Python（Flask / FastAPI）
- 数据库：PostgreSQL
- 决策树：scikit-learn（分类模型）
- PDF生成：ReportLab / WeasyPrint
- API对接：requests + 定时任务（Celery）

### 5.3 成本预算

**Phase 2成本**（Month 4-6）：

## 6. Go/No-Go标准

### 6.1 验证条件（Phase 1结束时）

**GO标准**（进入Phase 2，满足全部条件）：
- ✅ 付费意愿验证：≥40%咨询者愿意付费
- ✅ 客单价验证：平均客单价 ≥ 200元
- ✅ 复购验证：≥50%客户产生第二次咨询
- ✅ 单位经济验证：LTV/CAC > 3:1
- ✅ 规模化可能性：≥80%问题可用决策树解决

**PIVOT标准**（调整方向，出现任一情况）：
- ❌ 付费转化率 < 40% → 改为"Token用量监测+优化建议"订阅制
- ❌ 复购率 < 30% → 改为一次性"选型+迁移"打包服务，提高客单价到1000元
- ❌ LTV/CAC < 2:1 → 降低CAC（纯内容获客）或提高LTV（增值服务）

**NO-GO标准**（停止项目，出现任一情况）：
- ❌ 8周累计付费客户 < 10人 → 市场需求不真实
- ❌ 客户满意度 < 60%（NPS < 6分） → 服务质量不达标
- ❌ 8周累计收入 < 2000元 → 付费意愿极低

### 6.2 继续条件（Phase 2结束时）

**扩大规模标准**（Year 1，满足全部条件）：
- ✅ 月收入 ≥ 10万元
- ✅ LTV/CAC > 5:1
- ✅ 订阅续约率 ≥ 70%
- ✅ 自动化准确率 ≥ 85%（用户满意度）
- ✅ 盈亏平衡达成

**调整标准**：
- 如月收入 < 10万元但 > 5万元 → 继续优化获客和转化
- 如LTV/CAC < 5:1但 > 3:1 → 优化获客渠道，降低CAC

**停止标准**：
- 如月收入连续3个月 < 5万元 → 商业模式不成立
- 如LTV/CAC连续3个月 < 2:1 → 单位经济不健康
