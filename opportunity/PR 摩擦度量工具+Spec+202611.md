## MVP 目标和用户

软件研发效能负责人买单，维护者和工程经理使用。 在获授权的样本上完整演示一次从接收输入到交付、复核和取证的流程。

**交付件和输入** 由只读 PR 时间线、审查状态和流水线结果生成等待分解和改造事项列表。

**对照流程** 对照代码托管自带 cycle-time 看板，用发布批次核对跨角色卡点解释所需工时。

## 功能和验收

| 功能 | 验收方式 |
|---|---|
| P0 · 录入样本和基线 | 记录样本来源、授权、日期与纳入理由，锁定对照范围。必填信息缺失则退回补齐。 |
| P0 · 生成或制作业务交付件 | 按下述试点样本覆盖正常项和例外项，验收人能复核每项结论所依据的输入。 |
| P0 · 复核和业务接收 | 记录复核人、修订项、操作时间与最终状态。触及场景边界时暂停，交还原流程负责人。 |
| P0 · 验收证据 | 交付原流程和试点结果的同口径对照，列出分子、分母、测量区间、缺测和失败项。 |
| P1 · 后续扩展 | 首次流程验收并出现真实购买信号后，评审接入频率、角色范围和数据覆盖。 |

**测量协议** 一个团队并行观察小 PR 与跨组 PR，将 reviewer 等待、CI 与返工分别计时。

**首轮验收门槛** 30条 PR 中等待阶段归类与维护者核验一致≥90%，每周报告人工整理耗时下降≥40%。

## 最小权限与异常处理

单一等待时长用来评价个人会失真，按团队和流程聚合，缺失事件显式标注。 样本授权、输入版本与人工修改均应可追溯。由业务验收人确认输出用途，原流程负责人能够停止试点并接回未完成任务。

## 业务验收

按仓库或组织每月收费，以一份两周复盘及下月续签验证预算。 状态按样本可用、试点交付、业务验收、付费确认逐项记录。评审结论为 **GO · 先验证需求，再决定试点**。已落实数据授权、业务负责人和对照基线后，方可启动受控试点。
