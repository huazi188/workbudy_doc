## MVP 目标和用户

用第三方客服的独立站店主采购，客服负责人核对自动解决口径。 在获授权的样本上完整演示一次从接收输入到交付、复核和取证的流程。

**交付件和输入** 用匿名对话量、转人工、重复咨询和账单导出，给出套餐成本分布及告警阈值。

**对照流程** 与当前档位比较，按周和活动峰值推算每个有效解决的合并成本。

## 功能和验收

| 功能 | 验收方式 |
|---|---|
| P0 · 录入样本和基线 | 记录样本来源、授权、日期与纳入理由，锁定对照范围。必填信息缺失则退回补齐。 |
| P0 · 生成或制作业务交付件 | 按下述试点样本覆盖正常项和例外项，验收人能复核每项结论所依据的输入。 |
| P0 · 复核和业务接收 | 记录复核人、修订项、操作时间与最终状态。触及场景边界时暂停，交还原流程负责人。 |
| P0 · 验收证据 | 交付原流程和试点结果的同口径对照，列出分子、分母、测量区间、缺测和失败项。 |
| P1 · 后续扩展 | 首次流程验收并出现真实购买信号后，评审接入频率、角色范围和数据覆盖。 |

**测量协议** 授权记录7天真实用量并加入前一促销周导出，模拟有效解决、转接、活动三种档位。

**首轮验收门槛** 账单抽核差异≤2%，重放活动量时预测超额次数差异≤10%，至少给出1项有凭据的调档理由。

## 最小权限与异常处理

供应商解决口径差异导致重复计费。固定重复联系统计窗口并核查订单与退款意图。 样本授权、输入版本与人工修改均应可追溯。由业务验收人确认输出用途，原流程负责人能够停止试点并接回未完成任务。

## 业务验收

每店每次审计报价，超量告警做月度复查，以首期付款和第二期复核采购验证。 状态按样本可用、试点交付、业务验收、付费确认逐项记录。评审结论为 **GO · 验证需求与付费**。已落实数据授权、业务负责人和对照基线后，方可启动受控试点。
