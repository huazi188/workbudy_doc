## MVP 目标和用户

中小服饰品牌商品经理付费，社媒运营、版师与售后共看需求摘要。 在获授权的样本上完整演示一次从接收输入到交付、复核和取证的流程。

**交付件和输入** 用授权评论、社群的脱敏反馈与退换货原因输出尺码、面料、颜色需求及证据样例。

**对照流程** 以人工日报和官方热词表为基线，比较可改款建议覆盖和从意见汇总到需求复核的时间。

## 功能和验收

| 功能 | 验收方式 |
|---|---|
| P0 · 录入样本和基线 | 记录样本来源、授权、日期与纳入理由，锁定对照范围。必填信息缺失则退回补齐。 |
| P0 · 生成或制作业务交付件 | 按下述试点样本覆盖正常项和例外项，验收人能复核每项结论所依据的输入。 |
| P0 · 复核和业务接收 | 记录复核人、修订项、操作时间与最终状态。触及场景边界时暂停，交还原流程负责人。 |
| P0 · 验收证据 | 交付原流程和试点结果的同口径对照，列出分子、分母、测量区间、缺测和失败项。 |
| P1 · 后续扩展 | 首次流程验收并出现真实购买信号后，评审接入频率、角色范围和数据覆盖。 |

**测量协议** 挑一款瑜伽背心并区分研发前、试穿后评论，跟踪可实施的单项改动和原尺寸版本。

**首轮验收门槛** 两周抽查200条，需求归类一致率≥85%，确认证据回溯率100%，商品经理采纳至少3条。

## 最小权限与异常处理

刷评或单一热门帖子把非普遍痛点放大。按渠道分层、去重并标样本来源。 样本授权、输入版本与人工修改均应可追溯。由业务验收人确认输出用途，原流程负责人能够停止试点并接回未完成任务。

## 业务验收

按品牌月巡检费或按活动收监测费，以试用后付费扩第二个款号衡量。 状态按样本可用、试点交付、业务验收、付费确认逐项记录。评审结论为 **GO · 验证需求与付费**。已落实数据授权、业务负责人和对照基线后，方可启动受控试点。
