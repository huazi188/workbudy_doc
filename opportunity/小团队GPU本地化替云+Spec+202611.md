## MVP 目标和用户

小设计团队老板采购，运营技术人员和内容员工试用同一任务。 在获授权的样本上完整演示一次从接收输入到交付、复核和取证的流程。

**交付件和输入** 交付年度云账本、现有本机显卡样板和容量报告，输入周调用、现云账单、工作集和电价。

**对照流程** 对照现云方案，在同模型级别记录成功吞吐、员工等候、能耗及分摊的软硬件成本。

## 功能和验收

| 功能 | 验收方式 |
|---|---|
| P0 · 录入样本和基线 | 记录样本来源、授权、日期与纳入理由，锁定对照范围。必填信息缺失则退回补齐。 |
| P0 · 生成或制作业务交付件 | 按下述试点样本覆盖正常项和例外项，验收人能复核每项结论所依据的输入。 |
| P0 · 复核和业务接收 | 记录复核人、修订项、操作时间与最终状态。触及场景边界时暂停，交还原流程负责人。 |
| P0 · 验收证据 | 交付原流程和试点结果的同口径对照，列出分子、分母、测量区间、缺测和失败项。 |
| P1 · 后续扩展 | 首次流程验收并出现真实购买信号后，评审接入频率、角色范围和数据覆盖。 |

**测量协议** 选一项高频的非敏感设计任务，回放既有调用日志和一周样本，拿云账单和功耗记账复核。

**首轮验收门槛** 拟采一周不少于100个获准任务，等效质量通过≥95%，中位完成时长不高于云基线，回收期用三档场景呈现。

## 最小权限与异常处理

忽略人工维护和硬件闲置会高估节约，把故障、折旧与高峰溢出费用单列，保留云回退可用性。 样本授权、输入版本与人工修改均应可追溯。由业务验收人确认输出用途，原流程负责人能够停止试点并接回未完成任务。

## 业务验收

按团队收测算，再按装机迁移和维保分段报价，以实付诊断及配置订单验证。 状态按样本可用、试点交付、业务验收、付费确认逐项记录。评审结论为 **GO · 验证需求与付费**。已落实数据授权、业务负责人和对照基线后，方可启动受控试点。
