## MVP 目标和用户

电商财务内控或客服合规负责人采购，争议坐席和二级审批人使用。 在获授权的样本上完整演示一次从接收输入到交付、复核和取证的流程。

**交付件和输入** 以合成退款工单、既有权限矩阵和规则版本交付证据清单、审批待办及可审计沙箱演示。

**对照流程** 对照客服跨页面抄录并人工对账，比较每单准备时长与审批资料完整率。

## 功能和验收

| 功能 | 验收方式 |
|---|---|
| P0 · 录入样本和基线 | 记录样本来源、授权、日期与纳入理由，锁定对照范围。必填信息缺失则退回补齐。 |
| P0 · 生成或制作业务交付件 | 按下述试点样本覆盖正常项和例外项，验收人能复核每项结论所依据的输入。 |
| P0 · 复核和业务接收 | 记录复核人、修订项、操作时间与最终状态。触及场景边界时暂停，交还原流程负责人。 |
| P0 · 验收证据 | 交付原流程和试点结果的同口径对照，列出分子、分母、测量区间、缺测和失败项。 |
| P1 · 后续扩展 | 首次流程验收并出现真实购买信号后，评审接入频率、角色范围和数据覆盖。 |

**测量协议** 覆盖多次提交、部分退款、超期申诉和账单不匹配，在沙箱由两岗分别签核。

**首轮验收门槛** 50条合成历史工单资料完整率≥95%，未审批扣款或退款0笔，重复申请可识别率100%。

## 最小权限与异常处理

越权退款或客户信息外泄会产生资金损失，生产资金操作始终走原审批系统与人员复核。 样本授权、输入版本与人工修改均应可追溯。由业务验收人确认输出用途，原流程负责人能够停止试点并接回未完成任务。

## 业务验收

按一个退款流程收固定验收费，用带内控审批的付费演示合同验证。 状态按样本可用、试点交付、业务验收、付费确认逐项记录。评审结论为 **HOLD · 先核对边界与证据**。需求和边界已确认后，方可启动下一阶段。未决条件留在问题清单上。
