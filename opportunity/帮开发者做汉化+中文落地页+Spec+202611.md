## MVP 目标和用户

维护有明确许可的开发工具或库的团队购买，中文开发者与技术文档管理员使用。 在获授权的样本上完整演示一次从接收输入到交付、复核和取证的流程。

**交付件和输入** 用已授权英文README、术语和安装样例交付中文README、独立落地页草案与版本同步说明。

**对照流程** 与浏览器直译或无中文文档相比，同一安装任务核对术语准确、命令留存及完成率。

## 功能和验收

| 功能 | 验收方式 |
|---|---|
| P0 · 录入样本和基线 | 记录样本来源、授权、日期与纳入理由，锁定对照范围。必填信息缺失则退回补齐。 |
| P0 · 生成或制作业务交付件 | 按下述试点样本覆盖正常项和例外项，验收人能复核每项结论所依据的输入。 |
| P0 · 复核和业务接收 | 记录复核人、修订项、操作时间与最终状态。触及场景边界时暂停，交还原流程负责人。 |
| P0 · 验收证据 | 交付原流程和试点结果的同口径对照，列出分子、分母、测量区间、缺测和失败项。 |
| P1 · 后续扩展 | 首次流程验收并出现真实购买信号后，评审接入频率、角色范围和数据覆盖。 |

**测量协议** 只选有明确贡献规则的3个开源项目，先获维护者同意，邀请5名中文开发者走新手流程。

**首轮验收门槛** 3个许可明确项目各作一版，命令或API参数变形0处，术语人工抽查准确率≥95%，至少1次实际合并。

## 最小权限与异常处理

第三方许可、商标及上游更新。每个项目确认译文可分发条件并记录原文提交版本。 样本授权、输入版本与人工修改均应可追溯。由业务验收人确认输出用途，原流程负责人能够停止试点并接回未完成任务。

## 业务验收

按项目规模收翻译与文档搭建费，版本更新另计，以维护者支付后续文档包为验证。 状态按样本可用、试点交付、业务验收、付费确认逐项记录。评审结论为 **GO · 验证需求与付费**。已落实数据授权、业务负责人和对照基线后，方可启动受控试点。
