## MVP 目标和用户

内部流程Agent产品负责人和工程师。 在获授权的样本上完整演示一次从接收输入到交付、复核和取证的流程。

**交付件和输入** 对常规业务任务测单次成本、完成质量与运行耗时。

**对照流程** 和原任务配置或现有应用手工处理比较。

## 功能和验收

| 功能 | 验收方式 |
|---|---|
| P0 · 录入样本和基线 | 记录样本来源、授权、日期与纳入理由，锁定对照范围。必填信息缺失则退回补齐。 |
| P0 · 生成或制作业务交付件 | 按下述试点样本覆盖正常项和例外项，验收人能复核每项结论所依据的输入。 |
| P0 · 复核和业务接收 | 记录复核人、修订项、操作时间与最终状态。触及场景边界时暂停，交还原流程负责人。 |
| P0 · 验收证据 | 交付原流程和试点结果的同口径对照，列出分子、分母、测量区间、缺测和失败项。 |
| P1 · 后续扩展 | 首次流程验收并出现真实购买信号后，评审接入频率、角色范围和数据覆盖。 |

**测量协议** 在隔离环境选格式转换或知识摘要，比较固定样本的端到端成本。

**首轮验收门槛** 固定≥40个业务任务，成本降低≥20%，通过率下降≤2个百分点。

## 最小权限与异常处理

仅降成本而牺牲准确性，预注册成功口径并保留原配置。 样本授权、输入版本与人工修改均应可追溯。由业务验收人确认输出用途，原流程负责人能够停止试点并接回未完成任务。

## 业务验收

按单个工作流收质检调优费，展示实测工时账单。 状态按样本可用、试点交付、业务验收、付费确认逐项记录。评审结论为 **GO · 验证需求与付费**。已落实数据授权、业务负责人和对照基线后，方可启动受控试点。
